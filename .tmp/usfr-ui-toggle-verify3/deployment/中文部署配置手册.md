# USFR 视频复刻服务中文部署配置手册

这份手册对应当前压缩包中的 Python 全量视频服务。部署后，Web 服务只需要把阿里云 OSS 素材 URL 提交给 USFR，不需要提交 SHA、文件大小、MIME、时长、分辨率、FPS、revision、Provider 参数或审核摘要。

## 1. 最终部署结构

服务由 5 个进程组成：

- `api`：对外提供三个 HTTP 业务接口。
- `worker`：执行视频拆解、脚本、故事板、生成、合成和质检。
- `sweeper`：清理 Redis 和 MinIO 临时数据。
- `redis`：保存短期任务、版本、审核、租约和 Provider 去重状态。
- `minio`：保存当前任务的临时媒体和中间文件。

数据分工必须保持如下：

- 用户上传的原始素材：永久保存在阿里云 OSS，USFR 不删除、不移动、不覆盖。
- 最终视频：由 USFR 上传到阿里云 OSS，永久保留。
- 下载副本、关键帧、音频、ASR、故事板、Seedance 输入输出、合成文件：只放在 MinIO，属于临时文件。
- 对外只开放 API 端口，Redis、MinIO 9000 和 MinIO 管理端口 9001 默认不对公网开放。

## 2. 服务器要求

必须安装：

- Docker Engine；
- Docker Compose v2；
- 可访问 OpenAI、RunningHub 和阿里云 OSS 的网络；
- 足够的 CPU、内存、临时磁盘和出口带宽。

视频的模型推理由 GPT、RunningHub、Seedance 等远程 API 完成；服务器主要承担下载、FFmpeg 探测、切片、合成、质检、队列和临时存储。

## 3. 最快启动方法

解压后进入工程目录，复制配置文件：

```powershell
Copy-Item .env.example .env
```

填写 `.env` 后执行：

```powershell
docker compose -f deployment/docker-compose.yml config
docker compose -f deployment/docker-compose.yml up -d --build
docker compose -f deployment/docker-compose.yml ps
docker compose -f deployment/docker-compose.yml logs --tail=200 api worker sweeper
```

浏览器或命令行检查：

```text
GET http://服务器地址:8080/healthz
GET http://服务器地址:8080/readyz
```

`healthz` 只表示 API 进程活着；`readyz` 返回 200 才表示 Redis、MinIO、Skill 包、模型能力和 Provider 配置全部可用。

## 4. `.env` 必填配置

### 4.1 服务与任务 Token

```dotenv
USFR_CAPABILITY_SECRET=至少32字节的高强度随机字符串
USFR_DEPLOYMENT_FACTORY=server.packaged_factory:build_runtime
USFR_PORT_FACTORY=server.packaged_ports:build_ports
USFR_PROFILE_MODE=shadow
USFR_API_PORT=8080
```

`USFR_CAPABILITY_SECRET` 用于派生任务级 `access_token`。不要使用示例值，不要提交到 Git，不要发送给 GPT 或 RunningHub。

### 4.2 允许导入的 OSS 域名

```dotenv
USFR_ALLOWED_OSS_HOSTS=*.oss-cn-hangzhou.aliyuncs.com,media.example.com
```

这里只填写 Web 可能提交的阿里云 OSS Bucket 域名或已备案的自定义 OSS/CDN 域名。服务拒绝 localhost、内网 IP、Redis、MinIO 管理地址和未授权域名，防止 SSRF。

### 4.3 内置 MinIO

```dotenv
USFR_S3_BUCKET=usfr-media
AWS_ACCESS_KEY_ID=请修改默认用户名
AWS_SECRET_ACCESS_KEY=请设置强密码
AWS_DEFAULT_REGION=us-east-1
```

MinIO 是临时工作区，不是最终视频仓库。容器重建会影响正在运行或待审核的任务，因此生产环境可为 MinIO 配置临时高速盘，但不需要把它当作永久素材库。绝对不要把 9000/9001 直接开放到公网。

### 4.4 阿里云 OSS 永久结果

```dotenv
USFR_OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
USFR_OSS_BUCKET=你的结果Bucket
USFR_OSS_ACCESS_KEY_ID=你的AccessKeyId
USFR_OSS_ACCESS_KEY_SECRET=你的AccessKeySecret
USFR_OSS_PUBLIC_BASE_URL=https://你的永久访问域名
USFR_OSS_FINAL_PREFIX=usfr
```

最终对象键格式：

```text
usfr/final/{job_id}/result.mp4
```

`USFR_OSS_PUBLIC_BASE_URL` 必须是 HTTPS 永久访问域名，可以是 Bucket 公网域名或 CDN 域名。服务返回的 `result_url` 来自这里。

OSS RAM 账号最少需要：

- 对结果前缀执行 `PutObject`、`GetObject`、`HeadObject`；
- 不给删除原始素材的权限；
- 不给删除最终结果前缀的权限更安全。

### 4.5 OpenAI

```dotenv
OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=
OPENAI_MODEL_CONFIG_SHA256=
```

GPT 只负责语义推理、拆解、脚本和受约束的编译判断。文件哈希、时长、MIME、路由槽位、任务版本和 Provider 去重由确定性代码完成，不应交给 GPT 重复推理。

### 4.6 RunningHub、Seedance、Whisper

```dotenv
RUNNINGHUB_API_KEY=
RUNNINGHUB_SEEDANCE_API_KEY=
RUNNINGHUB_BASE_URL=https://www.runninghub.ai
RUNNINGHUB_SEEDANCE_CREATE_URL=https://www.runninghub.ai/openapi/v2/bytedance/seedance-2.0-fast-token/multimodal-video
RUNNINGHUB_SEEDANCE_QUERY_URL=https://www.runninghub.ai/openapi/v2/query
RUNNINGHUB_SEEDANCE_UPLOAD_URL=https://www.runninghub.ai/openapi/v2/media/upload/binary
RUNNINGHUB_SEEDANCE_CONFIG_SHA256=
RUNNINGHUB_WHISPER_WORKFLOW_ID=
RUNNINGHUB_WHISPER_INPUT_NODE_ID=12
RUNNINGHUB_WHISPER_INPUT_FIELD=audio
SEEDANCE_API_PROVIDER=runninghub_standard

USFR_UPLOADED_AUDIO_CLASSIFIER_ENDPOINT=
USFR_UPLOADED_AUDIO_CLASSIFIER_MODEL_ID=
USFR_UPLOADED_AUDIO_CLASSIFIER_MODEL_SHA256=
USFR_UPLOADED_AUDIO_CLASSIFIER_API_TOKEN=
```

歌曲反推只读取指定 Whisper/歌曲工作流返回的 TXT 歌词。最终指定语言对口型和 Seedance 无法可靠完成的唱歌对口型继续使用工程内已配置的 RunningHub 工作流，不由公共 API 调用方提交内部工作流参数。

上传音频分类器用于在文字脚本生成前判定“歌曲”还是“非歌曲”，并把实际导入的音频 SHA、模型 ID、模型文件 SHA、请求 SHA 和响应 SHA 冻结到分类证据中。只有歌曲才进入歌词、演唱人物和唱歌对口型路线；非歌曲只按原视频音乐切入切出窗口替换背景音乐。

- 不开放 `audio` 输入时，四项可以全部留空。
- `ENDPOINT`、`MODEL_ID`、`MODEL_SHA256` 必须同时填写；只填一部分会让服务启动失败。
- `API_TOKEN` 只有分类服务要求 Bearer 鉴权时才填写。
- active/production 模式必须使用 HTTPS。
- 用户提交了 `audio`，但分类器未配置、低置信度、返回证据与实际音频不一致时，任务会在付费生视频调用前阻断。

## 5. Web 端只需要调用三个接口

### 5.1 创建并自动开始

```http
POST /api/v1/jobs
Idempotency-Key: Web为本次提交生成的UUID
Content-Type: application/json
```

最小示例：

```json
{
  "source_video": "https://bucket.oss-cn-hangzhou.aliyuncs.com/source.mp4",
  "new_model_images": [
    "https://bucket.oss-cn-hangzhou.aliyuncs.com/model.jpg"
  ]
}
```

完整可选字段：

```json
{
  "source_video": "https://bucket.oss-cn-hangzhou.aliyuncs.com/source.mp4",
  "new_product_images": ["https://bucket.oss-cn-hangzhou.aliyuncs.com/product.jpg"],
  "new_model_images": ["https://bucket.oss-cn-hangzhou.aliyuncs.com/model.jpg"],
  "ui_screenshots": ["https://bucket.oss-cn-hangzhou.aliyuncs.com/ui-1.jpg"],
  "app_store_url": "https://apps.apple.com/app/id000000000",
  "ui_operation_video": "https://bucket.oss-cn-hangzhou.aliyuncs.com/ui-operation.mp4",
  "tail_video": "https://bucket.oss-cn-hangzhou.aliyuncs.com/tail.mp4",
  "audio": "https://bucket.oss-cn-hangzhou.aliyuncs.com/music.mp3",
  "output_language": "en"
}
```

`source_video` 必传，且最长 30 秒；其他选项至少提交一个，可以复合提交。

成功响应：

```json
{
  "job_id": "任务ID",
  "access_token": "任务级Token",
  "status": "importing"
}
```

同一个 `Idempotency-Key` 加完全相同的请求体重复提交，会返回同一个任务和同一个可重新派生的 Token，不会重复导入和重复付费。相同 Key 搭配不同请求体会被拒绝。

### 5.2 查询任务

```http
GET /api/v1/jobs/{job_id}
Authorization: Bearer <access_token>
```

对外状态只有：

- `importing`：正在下载和探测 OSS 素材；
- `processing`：正在分析、生成或合成；
- `waiting_review`：等待用户处理文字脚本或故事板；
- `completed`：最终视频已经上传到 OSS；
- `failed`：任务无法继续。

等待脚本时，响应包含：

```json
{
  "status": "waiting_review",
  "stage": "script",
  "review": {
    "type": "script",
    "content": "可编辑的两段式 Markdown 文字脚本"
  }
}
```

等待故事板时，响应包含预览图 URL。完成时只返回永久 `result_url`，不返回内部对象键、SHA、revision 或 Provider 任务信息。

### 5.3 修改或确认

确认当前内容：

```http
POST /api/v1/jobs/{job_id}/review
Authorization: Bearer <access_token>
Content-Type: application/json

{"action":"approve"}
```

修改脚本或给故事板重做要求：

```json
{
  "action": "revise",
  "content": "完整修改后的两段式 Markdown 文字脚本，或故事板修改要求"
}
```

服务端自动识别当前审核类型、当前 revision、SHA 和 CAS 版本。客户端禁止自行传这些内部字段。

所有公共提交路线固定先确认文字脚本，再确认故事板。用户只处理这两个确认点。故事板确认后，Seedance 编译、提交、等待、合成、QA 和 OSS 上传全部自动继续。

## 6. 七个素材入口与路由

| 输入 | 作用 |
|---|---|
| `source_video` | 必传爆款原视频，最长 30 秒 |
| `new_product_images` | 新实物商品或目标产品视觉事实 |
| `new_model_images` | 新人物身份和外观事实 |
| `ui_screenshots` | 新 UI 页面、文字、按钮和布局事实 |
| `app_store_url` | Apple App Store 或 Google Play 官方证据 |
| `ui_operation_video` | 直接替换原视频已识别的 UI 操作区间 |
| `tail_video` | 替换原视频尾部 App/CTA 区间 |

`audio` 是可选扩展，`output_language` 是独立参数，不改变七个固定素材入口。

关键路由规则：

- UI 操作视频优先于 UI 重建，只替换原视频中的 UI 区间，默认不用它的音轨。
- 同时提供 UI 截图和 UI 操作视频时，操作视频负责动作，截图负责样式、文字和关键状态校准。
- 只有截图且确定性 UI 重建是最优解时，才按 UI 区间使用受限重建适配器，禁止全局运行 ShotCraft/Remotion。
- `USFR_UI_REBUILD_ENABLED=false` 为默认值：没有 UI 截图、Google Play/App Store 链接时，检测到原片 UI 也保持源 UI，不做重绘、OCR 或商店解析；设为 `true` 后才允许人物/商品/语言替换触发自动 UI 重绘。
- 只要提交 UI 截图或官方 Google Play/App Store 链接，就视为明确的 UI 目标证据，始终开启 UI 目标链路，不受上述默认开关关闭影响；原 UI 操作时序仍按源视频保持不变。
- 上传音频且源视频是唱歌 MV 时，执行歌词提取、人物唱歌脚本编译和必要对口型；非 MV 时只替换背景音乐。
- 复合需求合并命中的局部能力，不退回全量重复分析。

## 7. 文件生命周期

长期保留：

- Web 已经上传到阿里云 OSS 的原始素材；
- `USFR_OSS_FINAL_PREFIX/final/{job_id}/result.mp4`。

临时数据：

- MinIO 中的下载副本；
- 关键帧、ROI、音频、ASR、OCR、故事板；
- Seedance 输入输出；
- 合成与 QC 中间文件；
- Redis 任务、审核、Provider 去重和租约记录。

默认 `USFR_TEMPORARY_RETENTION_SECONDS=0`：任务最终成功或最终失败后，MinIO 工作文件立即进入任务级清理队列；正在运行、等待文字脚本确认、等待故事板确认或 Provider 尚未结束的任务不会被提前清理。Redis 任务状态和访问 Token 默认独立保留 7 天，方便 Web 查询最终结果。

清理器只按任务级精确前缀删除临时对象。阿里云 OSS FinalStore 会重新校验最终对象键、SHA、大小和 MIME；即使执行清理，也不会删除原始 OSS 素材或永久最终视频。

## 8. 常用运维命令

```powershell
docker compose -f deployment/docker-compose.yml ps
docker compose -f deployment/docker-compose.yml logs -f api worker sweeper
docker compose -f deployment/docker-compose.yml restart api worker sweeper
docker compose -f deployment/docker-compose.yml up -d --build
```

不要执行 `docker compose down -v`，除非确认可以清空 Redis 和 MinIO 中所有正在运行或待审核任务。该操作不会删除外部阿里云 OSS，但会导致未完成任务不能继续。

## 9. 验证 HTTP

无 Docker 环境可先运行真实本地 TCP 冒烟测试：

```powershell
python -B -m validation.e2e.local_public_http_smoke
```

有 Docker 的服务器运行完整容器控制流验证：

```powershell
$env:USFR_CAPABILITY_SECRET="至少32字节随机字符串"
$env:USFR_DOCKER_TARGET="e2e"
$env:USFR_PORT_FACTORY="validation.e2e.ports:build_ports"
$env:USFR_INSTALL_MODE="control-plane"
docker compose -f deployment/docker-compose.yml --profile e2e up --build --abort-on-container-exit --exit-code-from e2e e2e
```

它会真实调用三个 HTTP 接口，并验证：

- OpenAPI 只暴露三个业务接口；
- 创建响应只有 `job_id`、`access_token`、`status`；
- 幂等重试不创建重复任务；
- 错误 Token 被拒绝；
- 先脚本、后故事板；
- 最终 URL 可下载；
- MP4 同时有视频流、音频流且可播放。

该验证使用确定性的测试生成端口，只证明 HTTP、Redis、MinIO、Worker、审核、合成和结果交付控制流，不代表商业成片质量。正式上线仍需使用真实 GPT、RunningHub、Seedance、ASR、TTS、对口型和 UI 能力做素材矩阵验证。

## 10. 常见故障

| 现象 | 常见原因 | 处理方式 |
|---|---|---|
| `/readyz` 返回 503 | API Key、模型 SHA、OSS、Redis、MinIO 或 Provider 配置缺失 | 查看 `api` 和 `worker` 日志中的 readiness 项 |
| 创建返回 `INVALID_REQUEST` | 缺少变化输入、URL 域名不在白名单或字段多余 | 按公共请求模型修正 |
| 创建后变成 `SOURCE_UNAVAILABLE` | OSS URL 无法下载、重定向到未授权域名或已失效 | 检查永久 URL 和域名白名单 |
| 返回 `SOURCE_TOO_LONG` | 原视频超过 30 秒 | 在 Web 上传前裁剪 |
| 返回 `ACCESS_DENIED` | Token 错误、过期或属于其他任务 | 使用创建响应中的对应 Token |
| 一直等待审核 | Web 没有调用 review，或修改后正在重生成 | 查询任务并展示当前 review |
| 最终 URL 为空 | OSS 权限、公共域名或上传校验失败 | 检查 `USFR_OSS_*` 配置和 RAM 权限 |

## 11. 上线检查清单

- [ ] `.env` 不含示例密码，未提交到 Git。
- [ ] 只开放 API 端口，Redis 和 MinIO 不对公网开放。
- [ ] OSS 源素材域名已加入白名单。
- [ ] OSS 最终结果 URL 是永久 HTTPS 地址。
- [ ] OpenAI、RunningHub、Seedance、Whisper 和对口型配置通过 readiness。
- [ ] `docker compose config` 通过。
- [ ] 本地 TCP 冒烟或容器 E2E 通过。
- [ ] 真实复合素材完整经过脚本和故事板两次确认。
- [ ] 最终 MP4 可播放，原始 OSS 素材与最终 OSS 视频未被清理器删除。
