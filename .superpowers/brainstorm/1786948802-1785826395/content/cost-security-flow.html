费用控制与 API Key 隔离

员工只调用你的 MCP；所有 Provider Key 永远留在服务器端。

每次准备产生付费调用前

1. 身份与所有权

账号有效；任务和 Source Master 属于当前员工。

2. 每日条数

默认每人每日最多 50 条；后台可随时修改。

3. 月预算

公司默认每月最多 ¥10,000；按已结算 + 已冻结额度计算。

4. 幂等与授权

绑定请求 SHA、批次授权和 Segment；防止重复扣费。

↓ 通过预检后冻结预计成本

允许执行

  • 余额与条数充足
  • 请求 SHA 尚未付费提交
  • 批次摘要和样片授权有效
  • Provider 请求由 Worker 服务端发出

阻止执行

  • 超过个人每日条数
  • 公司月预算已用尽
  • 批次清单被修改
  • Provider 状态不明却尝试重复提交
预算分级策略（全部后台可配置）

0–69%

正常运行。

70%

向管理员发出预算提醒。

90%

提醒升级；后台可选择降低并发或限制新批次。

100%

停止新的付费调用；不重复取消已经成功提交的 Provider 任务。

Key 安全边界

员工能看到

job_handle、状态、脚本、故事板、成片和公开错误。

员工不能看到

OpenAI、RunningHub、OSS Key，Job capability，内部 Prompt 和 Provider payload。

服务器保存

部署 Secret / 环境变量；日志自动脱敏；开发与生产 Key 分离。

ZIP 安全处理

现有 ZIP 的非空密钥不得复制到新工程；部署前创建或轮换生产密钥。

MVP 账号边界：管理员创建/停用账号、密码安全哈希、登录失败限流、操作审计；暂不做 SSO、MFA、设备/IP 和单会话限制。
