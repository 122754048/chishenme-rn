# USFR 高保真故事板、音频演出与受限 UI 重建优化目标

## 目标

在不改变 USFR 既有 7 个固定输入槽位、12 个语义阶段、两次用户确认、最多两个 Seedance 生成段和源视频节奏的前提下，补强以下能力：

1. 两段故事板中的人物、服装和动作交接稳定一致，并且用户只需要完成一次故事板修改确认。
2. 对源视频做一次完整的文字、台词、音乐和人物说话关系反解，生成可编辑、可确认的新商品/App 脚本。
3. 将念白、演唱、说话人、时间窗和节拍编译为 Seedance-20 的不可改写合同，提高人物说对话、唱歌词与口型的准确性。
4. 开放可选的音乐上传：在满足证据条件时，让广告人物随上传歌曲演唱，同时最终音轨准确使用用户上传音乐，并保持原视频音乐的入点、出点和节奏结构。
5. 仅在适合确定性重建的 App UI 片段中，提供受限的 `remotion_react_ui` 适配器；不安装、不合并、不全局运行 Video ShotCraft。

最终目标不是增加更多全局推理，而是让每一种工具只在它能明显提高该片段质量或速度时被调用；不满足条件时直接走当前最快、最稳定的既有路径。

## 不可变约束

- 源爆款视频始终必传，所有替换、生成、音频和 UI 决策都以源视频的时间轴为准。
- 保持 7 个固定槽位：`source_video`、产品图、模特图、UI 截图、App Store URL、UI 操作视频、尾部视频。
- `background_music` 仅是 `input-contract-v2` 的可选扩展，不成为第八固定槽位，不改变固定槽位排序或角色判断。
- 保持现有两个用户确认点：反解脚本确认、故事板确认；不得为本目标新增第三次用户审批。
- 普通复刻最多两个 Seedance 生成段；不因音频、UI 或故事板能力额外增加视频生成段。
- 不重写原视频 Cut 顺序、镜头节奏、转场、CTA 时机和源视频音乐的入点/出点。
- 原视频、用户 UI 操作视频、用户尾部视频禁止作为常规 Seedance 视频参考；不透明 UI/尾部素材只能确定性拼接。
- 只长期保存 `final/{job_id}/result.mp4`。故事板、ASR、音频片段、歌词合同、UI 临时渲染、Provider 返回和 QC 证据均属于任务临时文件，随 Job TTL 清理。
- 所有 Provider 调用仍受现有审计 SHA、幂等、失败对账和最多重试策略约束；禁止为追求音频效果盲目创建重复付费任务。

## 全局工具使用原则

工具不是默认关闭，而是条件化自动选择：满足触发条件且它是当前片段的最优解时，直接调用；其余片段不得为“流程统一”而被拖入额外推理或渲染。

| 能力/工具 | 直接启用条件 | 不启用时的替代路径 | 禁止全局化的原因 |
| --- | --- | --- | --- |
| RunningHub Whisper | 源视频存在人声、歌词或需要替换/保留音频文字 | 无人声或纯技术 UI/尾部区间直接跳过 | 避免重复 ASR 和无效云端等待 |
| 说话人分离与人脸/口型对应 | 同一时间窗有两个以上潜在说话者，或说话人与镜头人物不明确 | 单人可见镜头采用确定的单说话人；低置信度进入脚本待指定 | 多人检测只对有台词 Cut 有价值 |
| Seedance-20 audio / characters | 已确认的生成段含口播、念白、演唱或多人物角色分配 | 无对话 Cut 使用明确 `No dialogue` 合同 | 不让所有静音镜头承担音频编译成本 |
| 音乐歌词/节拍分析 | 用户上传背景音乐，或源音乐有可见演唱/节拍动作 | 普通无歌词 BGM 仅保留音乐时间窗 | 不把每段环境音误当歌曲处理 |
| `remotion_react_ui` | 满足本文“受限 UI 适配器触发条件”的 UI 区间 | FFmpeg/既有 deterministic UI renderer | Remotion 对非 UI 片段没有质量收益，且增加渲染耗时 |
| Video ShotCraft 思路/组件 | 仅为受限 UI 适配器借鉴页面采集和白名单 2.5D 动作 | 不引入 | 禁止其模板、镜头卡、BGM、SFX 改写爆款节奏 |

每个工具调用必须在 `timing_log.json` 中记录 `enabled`、`skipped`、原因、耗时和输入证据 SHA。一次成功的源分析、ASR、App Store 解析、歌词/节拍分析必须被后续阶段复用，禁止因选择了专业 Skill 再跑一次完整视频分析。

## 目标一：双故事板一致性与一次确认

### 预期行为

当最终计划需要两张故事板/两个生成段时，系统先在后台生成一组故事板，不把第一张单独发给用户确认。第二张必须继承第一张已生成故事板的结尾状态，再通过自动一致性检查。两张均通过后，作为一个 storyboard revision 让用户一次性修改和确认。

### 内部连续性合同

在既有 `continuity_manifest.json` 中增加或严格化以下内部字段：

- `character_identity_lock`：人物身份、发型、脸部可见特征、体型和肤色。
- `wardrobe_lock`：上衣、下装、鞋、饰品、颜色、图案、材质、领口、袖长、妆容、眼镜、纹身等可见固定特征。
- `product_interaction_lock`：产品位置、持握手、朝向、接触点和产品状态。
- `segment_01_final_state`：第一段结束姿势、表情、视线、手势、镜头方向、环境和光线。
- `segment_02_opening_state`：第二段首帧必须匹配的承接状态。
- 第一张故事板中人物区域的审核摘要和视觉特征摘要，仅用于连续性校验，不作为新的公共输入。

### 后台自动修复规则

1. 第一段按人物锁、产品锁、源视频镜头结构生成。
2. 第二段输入必须含人物/产品参考、第一段故事板、`wardrobe_lock`、第一段结束状态和第二段起始合同。
3. 自动检查服装主色、图案、版型、饰品、发型、肤色/纹身、产品手位、画面左右方向和动作交接。
4. 高优先级不一致时，只重生不合格故事板；不得重置脚本、重新分析源视频或新增用户审批。
5. 两张均通过后，展示“第一段结束状态 / 第二段起始状态”的并排对照，用户只进行现有的一次故事板修改确认。

### 验收标准

- 两段故事板只有一个 revision 和一次故事板确认入口。
- 第二段未携带第一段连续性输入或服装锁时，必须在生成前失败。
- 自动检查发现高优先级换装、换饰品、换产品持握手或换镜头方向时，不能进入 Seedance 提交。
- 用户修改任何影响连续性的故事板内容后，重新生成整对故事板或受影响板，并重新校验后再进入同一确认入口。

## 目标二：源视频文字、音频与多人说话人反解

### 一次分析产物

在现有 `analyze_dynamics` 中，复用一次音频提取和 RunningHub Whisper 时间戳转写，生成与 Cut 时间轴绑定的 `source_content_timeline`。它包含：

- 画面文字：标题、字幕、卖点、CTA、品牌词、可读 UI 文本的出现/消失时间；
- 人声音频：口播、对话、旁白、念白、演唱或不可辨识音频；
- 音乐：BGM 入点、出点、歌词、人声段、节拍锚点、转场音效和有意义静音；
- 视觉卖点：每个 Cut 的动作、镜头、产品证明、情绪变化和 CTA 角色；
- 证据来源、置信度和不确定性。

画面文字按连续显示区间记录精确毫秒，不逐秒重复 OCR；前端可将区间投影为逐秒查看列表。UI 文本仍必须走既有确定性 UI 重建/OCR 路径，不能由视频模型生成可读 UI 字。

### 多人说话人分配

Whisper 只提供“何时说了什么”。多人分配采用按需组合：

1. 仅对存在文字人声的 Cut 运行说话人分离；
2. 将每个发声时间窗与画面中可见人物、嘴部可见性、口型活动和镜头切换对应；
3. 输出稳定角色标签 `CHARACTER_A`、`CHARACTER_B`、`VOICEOVER`，以及分配置信度与证据；
4. 高置信度可自动进入脚本；低置信度显示为“待指定说话人”，由用户在现有反解脚本确认页指定；
5. 未确认的多人归属不能进入最终 Seedance 编译或 Provider 任务。

### 新卖点脚本

对每一个可替换的源文字/台词，输出：

`源句作用 → 新产品/App 功能 → 机制 → 用户利益 → 可证明内容 → CTA`。

脚本确认页每行要显示原文字/原台词、角色、时间、目标文字/新台词、目标证据、是否为字幕/口播/演唱/UI。用户修改后必须重新进行时长、音节、节拍、说话人和镜头可见性检查。

### 验收标准

- 每个有声音的生成 Cut 有对应的时间戳文字、音频角色和置信度；不确定内容明确标记，不能被伪装为事实。
- 多人同时存在时，每句必须有一个确认的说话人标签，或被阻断等待脚本修改。
- App Store URL 只在 `generated_ui_demo` 确实会消费官方 UI 证据时解析一次；不得把网页 HTML 交给生成模型。
- 不支持或无法证明的卖点必须降级或删除，不得编造机制、统计、效果、评价或承诺。

## 目标三：Seedance-20 念白、演唱与最终脚本编译

### 角色定位

Seedance-20 不负责猜测谁说话、歌词是什么或用户想表达什么。它负责把已确认的脚本、人物分配、节奏和镜头条件编译为可审计的生成约束，并阻止最终 Prompt 偏离这些约束。

### 逐句合同

每句声音内容必须成为 `performance_line_contract` 和既有 `line_contract` 的关联记录，至少包含：

- `line_id`、`cut_id`、人物标签、人物角色和可见性；
- 类型：`spoken`、`sung`、`instrumental`、`inaudible`；
- 精确文本、语言、规范化文本和发音备注；
- 全局开始/结束毫秒、分段本地时间、节拍锚点；
- 念白/演唱方式、情绪、强调、口型风险；
- 嘴部可见性、遮挡、头部运动限制、动作与表情边界；
- 卖点证据、FoIey、静音和音乐策略；
- ASR、人物归属、语言、口型和节拍 QC 要求。

### 编译流程

1. **Invocation A，脚本确认前：** 验证逐句文本是否装得进原视频时间窗，是否跨越 Cut/Segment，是否与说话人、画面可见性、节拍和新卖点证据冲突。
2. **脚本确认：** 用户可改台词、歌词和说话人；系统重新验证合同，不合格时给出明确压缩/改镜头建议。
3. **Invocation B，故事板确认后：** 只消费已确认合同，以同一 Seedance-20 快照重新编译最终 Prompt；完整输出谁在何时念白/演唱哪句，禁止改写、增词、漏词、换人或跨 Segment。
4. **生成后 QC：** ASR 回转录、角色归属、台词/歌词起止、节拍动作和口型一致性均需检查；失败仅回到相关脚本/音频合同或重生相关生成段，不重新跑全片分析。

### 验收标准

- 最终 Prompt 的每句文本、人物、语言和时间均可追溯到已确认合同。
- 成片中出现未批准文字、错误人物、错误语言、超出时间窗或跨 Segment 台词时，必须阻断交付。
- 演唱必须使用精确歌词合同；歌词证据不可靠时，只能标为伴奏/不可辨识，不能宣称人物准确演唱。
- 最终脚本无论是否音乐上传，都必须经过 Seedance-20 编译和现有完整性审计后才可发送 Provider。

## 目标四：上传音乐与人物唱歌

### 输入与路由

`background_music` 为可选音频扩展。上传音乐存在时，系统必须走标准复刻路线，不能误走 language-only 快通道。它以 Youdao Audio 资产注册，并仅作为内容项 `audio_url`、`role=reference_audio` 传入，Prompt 使用 `@Audio1`；顶层 `reference_audios` 始终禁止。

### 两种工作模式

#### A. 可验证演唱模式

只有在上传音频能得到可靠歌词、人声区间和节拍锚点，且脚本确认了演唱者与歌词时启用。

- 解析上传音频中的人声、伴奏、歌词和节拍；
- 让用户在现有脚本确认页确认演唱片段、歌词、角色、是否允许翻译/改词；
- 为每段可见演唱建立逐句 `performance_line_contract`；
- Seedance-20 将 `@Audio1`、精确歌词、人物、时间窗、节拍、口型限制编译为最终 Prompt；
- 视频生成只负责人物表演和口型；最终成片音轨以经验证的用户上传音频片段为权威，不能用模型生成歌曲替代；
- 对歌词/音素对齐、口型、节拍和音乐入出点进行最终 QC。

#### B. 背景音乐替换模式

当音频是纯伴奏，或歌词不可靠且用户未提供已确认歌词/时间轴时启用。

- 可替换 BGM，并保持源视频音乐入点、出点、静音和转场节奏；
- 不生成“人物准确唱歌词”的承诺；
- 若人物可见，只能做非歌词的节拍表演或无口型表演。

### 音乐时间轴要求

- 以源视频音乐窗口为输出时钟：切入、切出、淡入、淡出、停顿和转场点必须保持一致。
- 上传音乐按已确认的连续片段填充这些窗口；禁止循环、变速、拉伸、变调、补黑、补静音或生成替代音乐。
- 上传音乐不足以覆盖确认窗口时必须阻断，不得自动延长或压缩。
- 最终混音回执必须绑定上传音频 SHA、每个已使用片段 SHA、输出窗口和最终视频 SHA。

### 验收标准

- 上传音乐不会改变 7 个固定槽位的含义或顺序。
- 音频资产注册为 `Audio`，请求中只有一个 `audio_url/reference_audio`，且 Prompt 含 `@Audio1`。
- 有可见歌手时必须有歌词/音素对齐和口型 QC；无可见歌手时明确记录跳过原因。
- 最终成片音乐片段、时间窗和音频 SHA 均可与上传文件核对；不允许变速、循环、变调或模型替代音轨。

## 目标五：受限 `remotion_react_ui` 适配器

### 明确边界

不安装 Video ShotCraft，不将其 Skill、模板、106 镜头卡、Ink Press 工程、BGM、SFX、自动选镜或节奏策略合入 USFR。仅借鉴其页面采集思路和少量 2.5D 页面运动设计，形成一个受限、可替换的现有 deterministic UI renderer 实现。

### 唯一触发条件

以下条件必须全部为真，才直接选择 `remotion_react_ui`：

1. 有用户 UI 截图或已验证的官方 App Store 截图；
2. 当前区间路由为 `generated_ui_demo`；
3. 源视频该区间允许确定性 UI 重建；
4. `ui_truth_card.json` 和 `ui_render_contract.json` 已冻结；
5. 原视频区间时长、画幅、旋转、安全裁切、转场壳、文字和布局已冻结；
6. UI 需要白名单 2.5D 层级运动，且 FFmpeg/当前 renderer 无法以相同质量或速度完成；
7. 当前部署已拥有对该版本适配器有效的同案例基准激活回执。

以下任一情况必须禁止：`opaque_ui_demo`、`source_ui_keep`、用户 UI 操作视频、尾部视频、无目标 UI 证据、没有冻结真值卡、需要模型猜 UI 文案、需要改变原视频节奏或未通过基准测试。

### 允许的渲染行为

- 严格复现冻结页面、组件坐标、字体、文字、画幅、时长、旋转和转场壳；
- 只允许白名单动作：轻微 perspective、分层 parallax、页面 translate、轻微 scale；
- 输出透明 UI 层或定长 UI MP4，交给既有完整时间轴渲染器拼接；
- OCR、布局、状态顺序和动画抽帧仍由独立既有 QC 验证。

禁止新增页面、镜头、字幕、音乐、SFX、转场风格、动效节奏或任何不在源视频 UI 区间合同内的元素。

### 启用与回退

适配器不是常驻后端：它是注册的候选 renderer。满足触发条件且有当前有效基准回执时自动选择；否则直接使用 FFmpeg/既有 deterministic UI renderer，不等待、不重试外部 UI 工具。

启用前必须在同一套黄金 App UI 案例上证明：

- 每一 UI 状态和动画抽帧 OCR = 100%；
- 布局 = 100%；
- 无黑帧、无错误裁切、无拼接跳帧；
- 输出时长、画幅、文字和转场壳完全一致；
- 候选实现的耗时不高于既有 renderer 基线，或在质量明显提升时不超过已批准性能阈值；
- 无任何 UI、卖点、时序或音频回归。

## 速度和质量目标

- 源视频探测、VLM 语义分析、Whisper ASR、OCR、App Store 解析各最多运行一次；后续阶段只读取冻结合同。
- 说话人分离、歌词/节拍分析、音频口型 QC 和 Remotion UI 渲染只对命中的片段执行。
- 无生成区域、无可见演唱者、无 UI 重建条件或无音频文字的路径必须显式记录 `skipped`，且不创建无用 Provider 任务。
- Invocation A 的 p50 不超过 30 秒、p95 不超过 60 秒、单次硬超时 120 秒；总非 Provider 主动处理增量不超过既有基线的 `min(120 秒, 10%)`。
- 所有新增候选工具必须用同案例的质量、耗时和独立 QC 回执进行评估；无回执即不能宣称可用。

## 完成定义

本目标完成必须同时满足：

1. 双故事板以成对生成、自动连续性校验和一次用户确认方式运行。
2. 源视频音频/文字时间轴、多人说话人分配和可编辑卖点脚本可在现有脚本确认流程中完整表达。
3. 所有最终口播、念白和演唱脚本均由 Seedance-20 Invocation B 编译、审计并绑定确认合同。
4. 上传音乐可在两种模式下安全运行，且可见演唱、最终音乐精确性和源视频音乐时间轴均被证明。
5. `remotion_react_ui` 只会在满足全部条件并通过基准时被选择，其他所有路径保持原有 renderer 和速度。
6. 相关自动化测试、黄金案例和回归测试通过；临时文件清理与最终视频唯一持久化策略无回归。
