# USFR 商业批量复刻：速度、质量与条件化工具使用目标

> 状态：待审核目标规格。本文定义要达成的能力、边界与验收线；不改变已确认的十二阶段主流程、七个固定槽位和两次人工确认。

## 1. 要解决的问题

把当前本地 MVP 跑通后，形成可服务端化的商业批量视频复刻能力：每条任务都以爆款原视频为依据，能按用户给出的商品、模特、App/UI、尾部视频、语言和音乐做替换；只对真正需要的区间调用相应工具，减少重复推理、重复 QA 和无效 Provider 调用，同时不削弱原视频拆解、卖点分析、深度复刻、App 商店证据解析及复杂组合需求。

优化的含义是“少做不会改变结果的工作”，不是降低拆解深度，也不是把所有任务降级为换人或换商品。原视频、品类、表现形式可以完全不同；系统必须按每条源视频的事实独立分析和路由。

## 2. 成功定义

一条成功任务必须同时满足以下目标：

1. 原视频为必传，时长不超过 30 秒；其余六个固定槽位、`output_language`、`background_music` 中至少有一项有效。只有原视频时不可创建正式任务或消耗 Provider。
2. 原视频从第 0 帧到真实结束帧只完成一次权威拆解；该拆解同时供脚本、卖点映射、故事板、提示词、合成和 QA 使用，后续不得重新做整段视频推理。
3. 每个源区间都有明确路由：保留源片段、生成替换、确定性合成、用户提供的不透明片段拼接、删除或意图级重述。未被用户输入影响的区间保持源片段，不进入生图、生视频或无意义的语义分析。
4. 常规复刻仅保留两次用户操作：确认“文字/台词/分镜脚本”及确认“整套故事板”。语言单改走既有快速通道，不出现这两次确认。内部校验、重试和 Provider 等待均不是用户确认点。
5. 每个生成结果都有输入、时间轴、版本、提示词、Provider 请求和 QC 的不可变绑定；付费请求不可因超时而盲目重复提交。
6. 成功交付后长期保存的媒体只有最终 `result.mp4`。上传件、解析、故事板、Provider 记录、缓存和 QA 均为任务级临时数据，成功后立即清理；失败或未完成任务按 TTL 清理，不建立跨用户、跨任务的素材历史库。

## 3. 固定输入与组合规则

| 输入 | 是否固定槽位 | 作用 | 未上传时的行为 |
| --- | --- | --- | --- |
| 爆款原视频 `source_video` | 是，必传 | 源事实、镜头、节奏、台词、音频和转场依据 | 拒绝创建任务 |
| 商品图 `new_product_image` | 是 | 替换实体商品、包装和商品证据 | 保留源商品 |
| 模特图 `new_model_image` | 是 | 替换人物身份、外貌与服装约束 | 保留源人物 |
| UI 截图 `ui_screenshot` | 是 | 重建可确定的目标 App/UI 状态 | 保留源 UI，除非另有 UI 操作视频 |
| App 商店链接 `app_store_url` | 是 | 取得官方身份、图标、截图和可验证 UI 证据 | 不抓取 App 商店 |
| UI 操作视频 `ui_operation_video` | 是 | 不透明地替换源 UI 区间 | 保留源 UI 或走确定性重建 |
| 尾部视频 `tail_video` | 是 | 不透明地替换源尾卡区间 | 删除源尾卡，不补黑帧、冻结帧或伪造尾卡 |
| 输出语言 `output_language` | 参数，不是槽位 | 语言本地化 | 保持源语言 |
| 上传音乐 `background_music` | 可选扩展，不是第八槽位 | 用作本任务的歌曲/背景音乐替换参考 | 保持源音乐与音频路线 |

### 3.1 组合需求的决定规则

所有输入先冻结到同一份源保真合同，再按 **Cut/区间** 路由，绝不按“整条视频只能走一种路线”处理。因此“改语言 + 换模特 + 换 App + 换 UI 操作 + 换尾部视频”是一个合法复合任务：人物/商品受生成区间锁定，UI 操作视频和尾部视频走不透明拼接，App 证据只服务于确实需要重建的 UI 区间，语言与台词进入脚本和最终提示词的精确时间窗。

- 仅改语言：走 RunningHub Whisper → 逐句翻译 → TTS/人工配音 → 原视频云端对口型的快速通道；不生成故事板、不调用 Seedance 2.0、不重新拆解镜头。
- 只上传原视频和音乐：走 `background_music_replace_sing`，不是语言单改/TTS 通道。上传曲目注册为 Audio 资产，在 Seedance 提示词中只能作为 `@Audio1` 出现；视频内可见人物需要演唱该歌曲。
- 语言与任一视觉替换同时出现：不再是“仅改语言”快速通道，进入常规复刻路线；语言台词、说话人和时间窗都写入脚本及 Seedance-20 编译产物。
- UI 操作视频优先于 UI 截图/App 链接对应的 UI 生成；该视频不做 OCR、语义改写、生图或生视频，只做时长、画幅、黑帧、旋转和音频策略校验后拼接。
- 没有尾部视频时删除源尾卡整个区间；不得为了“补齐时长”调用任何生成工具。

## 4. 完整工作流目标

```text
上传与校验
  → 一次探测 / 一次源事实拆解 / 一次音频转写
  → 按区间选择工具与冻结源保真合同
  → 卖点、字幕、台词和说话人映射
  → 用户确认脚本（语言单改除外）
  → 生成一套连续故事板
  → 用户一次确认整套故事板
  → Seedance-20 编译、审计和一次受控提交
  → 生成 / 确定性 UI 重建 / 不透明片段拼接
  → 合成、时间轴 QA、源保真 QC
  → 仅交付最终 MP4，清理临时数据
```

### 4.1 一次源拆解必须产出的事实

除“仅改语言”快速通道外，系统对原视频做一次从第 0 帧到结束帧的深度分析，产出并缓存于当前任务：

- Cut 边界、每段时长、画幅、镜头景别、相机运动、动作起点/终点、转场、源 UI/尾卡区间和可替换图层；
- 人物、服装、发型、饰品、手持物、商品、空间关系、光线、视线、姿势和跨镜头连续性；
- 每秒可见文字、字幕、CTA、Logo/图形的时间、位置和文字内容；需替换的叠加层另冻结几何与层级；
- 单独抽取音频后，以带时间戳的 RunningHub Whisper 结果记录对白、旁白、演唱歌词、背景音乐、音效、环境声和有意义的静音；
- 每个事实的证据帧/音频时间、置信度、不确定性和影响等级，避免把推测当成原视频事实。

分析只做一次；脚本、故事板、Seedance-20 Invocation A/B、拼接和最终 QC 必须复用同一摘要、同一音频合同和同一证据哈希。若证据校验失败，应明确阻断或只重做失败的小范围证据，不得悄悄重新跑完整视频。

### 4.2 台词、文案与多人说话人目标

脚本确认页必须同时给出“源事实”和“待替换内容”，而非只给一段新文案：

| 必须显示的列 | 目的 |
| --- | --- |
| 原始起止时间、Cut 编号、画面人物/画外来源 | 保证节奏和镜头不被改写 |
| 源文字/源台词/歌词、来源类型和置信度 | 区分字幕、旁白、演唱与 BGM |
| 说话人角色、可见说话人证据和口型风险 | 解决多人情况下“谁说哪句” |
| 新商品/App 的已验证卖点及证据 | 只改真实可支持的卖点 |
| 候选新文案/目标语言/目标说话人/精确时间窗 | 供用户编辑和一次性确认 |
| 未确认项和不确定项 | 禁止模型擅自补充宣传承诺 |

多人处理采用“音频分段/声纹聚类 + 画面可见说话人和口型时序交叉验证”。每句必须归到 `speaker_id`：可见人物、画外旁白、合唱/群体或未知。无法可靠归属时，标记为“待用户确认”，不把它强行分给某个人；未知台词可保留源音频，或在用户确认脚本后改成明确的旁白角色。Seedance-20 负责在最终提示词中锁定已确认的说话人、语言、逐句窗口、演唱/念白方式、音素/口型风险和静音/音效窗口；它不负责凭空判断原视频里是谁在说话。

## 5. 故事板：双板连续性与一次确认

当生成区间在 15 秒以内，只生成一张故事板和一个视频任务。超过单段安全上限、且有已批准的自然 Cut 边界时，才生成两张故事板和最多两个视频任务；不得为了均分时长强行切镜头，也不得创建第三张故事板。

两张故事板的目标不是让用户确认两次，而是让系统在内部完成连续性锁定后，将它们作为 **一个故事板套件** 一次性呈现、一次确认：

1. 在生成前冻结 `continuity_manifest`：同一人物身份、服装/颜色/材质、发型、饰品、妆容、商品型号/包装、场景和光线锚点，以及段 1 末帧到段 2 首帧的交接状态。
2. 先生成段 1；段 2 的生成必须同时使用原始人物/商品参考、同一连续性清单和段 1 已验收的画面作为连续性参考，不能只复用文字描述。
3. 系统内部对两板检查人物身份、服装、商品、环境、光线、时间码和 Cut 编号一致性。段 2 不达标时，仅在内部对段 2 受控重绘；不再要求用户先确认段 1。
4. 两张图都合格后，以全局 Cut 编号、各段局部时间码、共同锁定项和变更摘要打包展示。用户只做一次“确认整套故事板”；任一张修改或边界调整会使整个套件重新进入该一次确认点。

故事板始终使用既有的固定提示词骨架与动态填充规则，输出 16:9、2K、中等质量的真实模型生成制作板。故事板不是长文本运输工具，变形文字不能作为提交 Seedance 的依据。

## 6. 上传音乐与人物演唱目标

`background_music` 是可选扩展；它不改变七个槽位的排序，也不要求用户上传。只有“原视频 + 音乐”时，将上传音频视为替换原视频背景音乐并让视频中可见人物演唱该歌曲的明确需求。

### 6.1 音乐时间轴合同

源视频拆解必须识别原音乐进入、退出、停顿、淡入淡出和被对白/音效覆盖的窗口。上传音乐必须建立一个不可变的音乐时间轴合同，包含：

- 原视频中每个可替换音乐窗口的起止帧/毫秒和淡入淡出曲线；
- 上传歌曲所取的准确连续片段、原始 SHA-256 和片段 SHA-256；
- 演唱歌词或可唱音节、对应的可见人物、演唱开始/结束和口型风险；
- 保留的对白、音效、环境声及其混音层级。

最终成片只能在这些批准窗口中使用上传曲目的原始连续片段；禁止循环、拉伸、变速、隐性改调或用 TTS 替代歌曲。若源视频没有可见人物可演唱，保留上传曲作为背景音乐并在 QA 中显式记录“不适用演唱”，不得伪造演唱合格。

### 6.2 生成与 QA

音乐先作为 Youdao Audio 资产注册，最终 Seedance 2.0 请求仅包含一个内容型 `audio_url`/`reference_audio` 项，提示词引用 `@Audio1`；禁止顶层 `reference_audios`。Seedance-20 在提交前编译并审计人物、歌词/音素、演唱窗口、镜头动作、切入/切出、混音约束和连续性，保证歌曲能力与视频生成用同一个冻结脚本。

交付前必须验证：上传音乐的 SHA 与实际使用片段一致；进入/退出时间与源音乐窗口一致；没有循环、冻结、变速或补黑；演唱区间具备歌词/音素对齐和口型 QA 收据；最终混音仍保留应保留的对白、音效和环境声。任何一项无法证明时阻断交付，而不是退化为“只把歌盖到视频上”。

## 7. 工具使用策略：自动选最优解，但有严格条件

“默认不启用”不等于“不使用”。系统应当根据已冻结的区间事实自动选择最优工具；条件不满足时跳过并记录原因，不能在每条任务上全局运行造成变慢。

| 工具/能力 | 自动使用条件 | 明确禁止的全局或误用 |
| --- | --- | --- |
| FFmpeg 探测、时间轴拼接、黑帧/流 QA | 每条正式任务；只做一次探测，按区间合成 | 为同一媒体重复探测、为了补时长循环/冻结/黑帧 |
| 运行时 GPT 源视频语义拆解 | 非“仅改语言”且存在会改变可见层的区间 | 因加载某个专项技能再全片重分析 |
| RunningHub Whisper | 需台词/歌词/语言本地化/声音事实的任务；每条源音频只转写一次 | 用无时间戳文本替代时间轴、在每个下游步骤再次 ASR |
| RunningHub TTS + 云端对口型 | 只有 `output_language` 是唯一变化时 | 与商品/模特/UI/音乐替换混合后仍走语言快速通道 |
| App Store 官方解析 | 有 App 链接且已路由到“需目标 UI 证据的确定性 UI 重建” | UI 保留、UI 操作视频不透明拼接或零生成区间时抓取页面 |
| Seedance-20 A/B、专项子技能与 Seedance 2.0 | 只有实际生成的语义区间；最终提示词必经根编译、提示词审计与反空泛检查。人物、镜头、动作、光线、音频、连续性专项仅按冻结因素加载 | 用于源 UI、用户提供 UI/尾部视频，或让其猜测未验证的 App/UI/卖点 |
| RunningHub Image2 故事板 | 有实际生成区间且脚本获确认；一次生成一套一或两张板 | 对源保留、UI 不透明拼接、删除尾卡区间出图 |
| `remotion_react_ui` 适配器（吸收 ShotCraft 的页面采集思路与少量 2.5D 组件） | **同时满足**：已提供 UI 截图；源视频该区间允许确定性 UI 重建；目标 UI 真值卡已冻结；UI 时长、画幅、转场、文字、布局能精确匹配；同案例 OCR、时序、黑帧、渲染耗时基准已通过 | 全局安装/合并 ShotCraft；使用其模板、镜头卡自动选型、BGM/SFX；改写原视频节奏；处理未提供截图、UI 操作视频或不能确定性重建的区间 |
| 确定性 UI 渲染器 | 有 UI 截图或已验证 App 商店像素，且目标状态可以被证明 | 让渲染器自创 UI 真相；OCR 低于 100% 仍交付 |
| `video-shotcraft` | 仅以上述受限适配器形式提供页面采集思路和有限 2.5D 组件 | 安装、合并或作为主工作流运行整个 ShotCraft skill |

`remotion_react_ui` 的选择结果必须持久化为区间级决策与耗时记录，包括“命中原因”或“跳过原因”、适配器版本/哈希、输入 UI 真值、源区间合同、渲染产物和独立 OCR/布局收据。没有真实生产注册入口、没有可审计持久化决策、缺少真值/时长/转场绑定，或基准未过时，自动回退到既有确定性 UI 路线，不允许宣称已启用。

## 8. 速度目标与质量不降级原则

### 8.1 加速方式

- 一次槽位绑定、一次探测、一次源语义/音频拆解；所有结果只在当前任务的生命周期内缓存复用。
- App 商店解析、UI 重建、故事板、图像资产和两个独立生成段仅在路由证明“会影响结果”时运行；相互独立且已冻结输入的资产/段可并行。
- 保留源 UI、源商品、源人物、源区间、用户 UI 操作视频和用户尾部视频走确定性拼接，不占故事板、图像资产或 Seedance 视频任务配额。
- 故事板最多两张、Seedance 视频任务最多两次；同一提示词版本只编译和 dry-run 一次；已知 Provider task ID 只恢复/查询，绝不新建重复任务。
- 把脚本确认与双板确认压缩为两个既有用户节点；双板由系统先做连续性 QC，再作为一个套件一次展示。

### 8.2 不允许为了速度牺牲的能力

以下能力必须完整保留：原视频逐 Cut 拆解、卖点/证据链分析、原视频的镜头和节奏复刻、App 商店官方信息解析、字幕/台词/音乐时间轴、多人说话人归属、商品和模特连续性、UI 文本与布局正确性、最终音画/黑帧/转场 QC。优化只取消重复检查和无影响的工具调用。

标准任务的生产目标为 30 分钟内完成活跃处理；用户审核等待单独计时，Provider 正常等待绝不能因达到目标被取消。新增高保真能力带来的非 Provider 开销相对匹配基线不得超过 `min(120 秒, 基线的 10%)`。任何新工具（包括 Remotion UI 适配器）只有在同案例质量不回退、无 UI/卖点回归且满足该延迟预算时，才能自动被选用。

## 9. 质量与阻断验收标准

### 9.1 全部任务

- 源视频和至少一个合法变化输入通过校验；输入角色只由槽位决定，不允许 AI 猜上传件用途。
- 每个高关键事实绑定帧/音频证据、置信度和路线；未支持的卖点必须降级、删除或交由用户改写。
- 复刻至少保持源 Cut 顺序、镜头构图/运动、动作逻辑、节奏、转场、CTA 位置和跨段连续性；变化项仅来自用户输入和已确认脚本。
- 最终 MP4 必须有有效音视频流、正确时长/时间轴、无拼接处黑帧、无无授权冻结/循环/变速；不透明 UI/尾部媒体仅做技术正确性判断，不擅自语义改写。

### 9.2 脚本与语音

- 源音频/可见文字都有带时间戳事实记录；多说话人每句有 `speaker_id` 或明确“未知待确认”。
- 新文案只能引用已验证的新商品/App 卖点；用户可在一次脚本确认中编辑后冻结。
- 最终 Seedance-20 编译产物必须逐句保留已确认的语言、说话人、毫秒窗口、念白/演唱方式、静音、音效和连续性；变化即回到相应确认点。

### 9.3 双故事板与 UI

- 两板中人物、服装、商品、环境、光线与段间交接状态一致；任一张变动会使整套板重新待确认。
- UI 重建逐状态 OCR 与布局均为 100%，并有状态间动画采样证据；源区间的画幅、旋转、时长、转场壳、文字和布局不允许被适配器改变。
- `remotion_react_ui` 若启用，必须同时通过同案例基准、产物绑定和完整审计；任一条件缺失即不能被选中。

### 9.4 上传音乐

- 使用上传音乐的音频哈希、片段和源音乐进入/退出窗口精确一致。
- 可见演唱区间有歌词/音素与口型 QA；没有可见歌手则显式记录不适用，不伪造通过。
- 不允许 TTS、循环、变速或独立背景音乐模板取代上传歌曲；混音保留冻结合同规定的对白、音效和环境声。

## 10. 批量化与数据生命周期目标

批量任务以“行”为隔离单位：每行有独立固定槽位清单、哈希、版本、两次确认、Provider 尝试、临时对象前缀和最终文件。相同素材只能在同一未完成任务内以哈希复用，不建立长期素材缓存，也不让一行的故事板、脚本、App 证据或 Provider 任务影响另一行。

服务端使用临时 Redis 状态、任务私有临时对象和可回收工作目录。工作器只能从已验证的任务对象物化媒体；任务成功后原子性保留 `final/{job_id}/result.mp4`，随即清理上传、临时对象、Redis 权威、分析、缓存、Provider 记录和 QA 记录。失败/取消任务也必须在定义的 TTL 到期后执行同等清理，且密钥不写入任务包、日志、提示词、结果或下载链接。

## 11. 必须覆盖的验收场景

| 场景 | 预期路径与关键证明 |
| --- | --- |
| 仅原视频 | 拒绝，不分析、不出图、不提交 Provider |
| 原视频 + 仅输出语言 | Whisper/TTS/云端对口型快速通道；无脚本/故事板确认、无 Seedance |
| 原视频 + 商品图或模特图 | 一次深拆、卖点/脚本确认、故事板确认、仅生成受影响区间 |
| 原视频 + App 商店链接/截图 | 只在确需重建 UI 时解析官方证据；UI 文本布局 100% 可证 |
| 原视频 + UI 操作视频 | 不透明拼接，不 OCR/不生图/不改写内容；验证画幅、时长、音频和转场 |
| 原视频 + 尾部视频 | 替换尾卡并自然结束；未上传尾部视频则删除源尾卡 |
| 原视频 + 上传音乐 | 音乐时间轴、`@Audio1`、可见人物演唱和最终音频/口型 QA 全部通过 |
| 原视频 + 语言 + 模特 + 商品 + App/UI + 尾部 + 音乐 | 同一合同内按区间混合路由；两次用户确认；不把不透明 UI/尾部送入生成模型 |
| 超 15 秒且需要两段生成 | 双故事板连续性锁定、内部 QC 后一次套件确认，最多两次视频任务 |
| 适合确定性 UI 的截图任务 | 自动选用受限 `remotion_react_ui`，并留下基准、决策、OCR、时序和渲染证据 |
| 不适合确定性 UI 的任务 | 自动跳过 Remotion，走既有 UI/源片段/不透明路线并记录跳过原因 |

## 12. 审核结论所需的交付物

本目标完成时，应能提供：

1. 本地 MVP 的上述场景测试结果，含真实 API 的生图、生视频、ASR/TTS/对口型及音乐演唱链路；
2. 每条测试的时间账本，证明没有重复全片推理、重复 ASR、重复故事板或重复 Provider 提交；
3. 双故事板连续性、多人台词归属、上传音乐、复合需求和条件式 UI 适配器的可核验收据；
4. 只保留最终视频的清理验证；
5. 服务端打包前的能力清单、配置模板和同案例基准报告。任何条件式能力未达验收线时必须保持未选中，不影响核心复刻流程可用。
