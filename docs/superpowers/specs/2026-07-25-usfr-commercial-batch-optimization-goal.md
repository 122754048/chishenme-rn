# USFR 商业化批量复刻优化：详细目标规格

> 状态：待审核。本文定义“做成什么、什么不能改变、怎样验收”；具体代码步骤以 [2026-07-24-usfr-performance-audio-ui-optimization.md](../plans/2026-07-24-usfr-performance-audio-ui-optimization.md) 为准。

## 1. 一句话目标

把 USFR 做成可本地验证、随后可封装为服务端批量任务的高保真视频复刻能力：每条任务必须以爆款原视频为准，按实际输入自动选择最合适的工具和最少的处理步骤，既保留原视频的深度拆解、卖点逻辑、节奏和镜头表现，又避免重复推理、重复 QA 和无效的付费生成。

这里的“批量”不是把一条视频套到许多模特上。每一条原视频都可能属于不同品类和表现形式，包含实体商品、App、服务、人物口播、屏幕录制或混合素材；每一条任务都必须独立理解自己的原视频，并按区间做不同的替换与保留。

## 2. 本期范围、交付边界与非目标

### 2.1 本期要交付的能力

1. 本地 MVP 能用真实 API 跑通生图、生视频、ASR、TTS、对口型、音乐、App UI 和最终合成的完整功能测试。
2. 功能测试通过后，以同一套输入合同、提示词合同和临时制品生命周期封装为服务端并发任务；服务端只负责接收任务、执行、交付最终视频和自动清理。
3. 支持商品、模特、App/UI、UI 操作视频、尾部视频、语言和上传音乐的单项及任意合法组合。
4. 在不增加人工步骤的前提下，补齐双故事板连续性、源内容时间轴、多人说话人分配、准确念白/演唱、音乐上传和受限 UI 重建。

### 2.2 明确不做的内容

- 不建设账号、用户体系、租户、订单、计费、历史作品库、运营后台、消息中心或数据分析。
- 不把 Video ShotCraft、它的模板、镜头卡、BGM、SFX、自动选镜或节奏策略安装/合并进 USFR。
- 不因新增能力新建第三个人工确认点，也不把常规复刻的 Seedance 生成段从最多两个扩展到更多。
- 不以“更快”为理由，跳过原视频深度拆解、卖点分析、App 官方证据、时间轴约束、关键连续性检查或最终质量门禁。

## 3. 不可改变的底线

1. **原视频是唯一源事实。** `source_video` 必传、最长 30 秒；所有镜头、节奏、转场、字幕、台词、音乐窗口、CTA、商品证明和人物表演都以它为时间基准。
2. **保留既有主架构。** 继续使用 7 个固定槽位、12 个语义阶段、最多两段 4–15 秒的 Seedance 生成段，以及“反解脚本确认 → 整套故事板确认”两次人工确认。
3. **一个任务只做一次完整源拆解。** 从第 0 帧到真实结束帧的探测、动态分析、语义理解、ASR、OCR、音乐/静音事件分析及 Cut 时间轴必须冻结为带 SHA 的任务制品。后续脚本、故事板、提示词、合成和 QC 只读取它，不能再次整片推理。
4. **所有决策按区间而非按整条视频作出。** 同一条任务可以同时保留源片段、生成替换片段、重建 UI、拼接用户 UI 视频、替换尾部视频和修改语言。一个区间不受用户输入影响时，必须保留源片段，不进入生图或生视频。
5. **工具按需自动选用。** “默认不全局运行”不等于“默认不使用”。当冻结事实证明某工具是该区间的质量/速度最优解时，系统直接启用；条件不满足时直接走既有最快稳定路径，并留下 `skipped` 原因。
6. **只持久化最终结果。** 成功后仅 `final/{job_id}/result.mp4` 长期保存。上传件、解析、故事板、音频切片、Provider 原始响应、提示词、QA、日志和缓存均为任务临时制品；成功后清理，未完成或失败任务由 TTL 清理。不得建立跨任务素材或历史文件库。
7. **付费请求必须可审计且不可盲目重复。** 每一次 CreateAsset/CreateVideo 绑定冻结的请求 SHA、合同版本和 Provider 尝试；超时或断连先对账，再决定恢复，绝不直接重复扣费提交。

## 4. 输入合同与组合需求目标

### 4.1 固定输入

| 输入 | 类型 | 目标作用 | 缺省行为 |
| --- | --- | --- | --- |
| `source_video` | 固定槽位，必传 | 原视频事实、结构、节奏、台词、声音和转场 | 拒绝创建任务 |
| `new_product_image` | 固定槽位 | 替换实体商品、包装及可验证商品画面 | 保留源商品 |
| `new_model_image` | 固定槽位 | 替换人物身份，并作为人物/服装连续性参考 | 保留源人物 |
| `ui_screenshot` | 固定槽位 | 重建可确定的 App/UI 状态 | 保留源 UI，除非另有 UI 操作视频 |
| `app_store_url` | 固定槽位 | 取得官方 App 身份、图标、截图和 UI 证据 | 不抓取 App 商店 |
| `ui_operation_video` | 固定槽位 | 将源 UI 区间作为不透明媒体替换 | 保留源 UI 或走确定性 UI 重建 |
| `tail_video` | 固定槽位 | 将源尾卡作为不透明媒体替换 | 删除源尾卡，不补黑帧、冻结帧或伪造尾卡 |
| `output_language` | 参数，不是槽位 | 本地化语言、台词和声音 | 保持源语言 |
| `background_music` | 可选扩展，不是第八槽位 | 替换本任务的音乐/歌曲，并作为演唱参考 | 保持源音频路线 |

创建任务的准入条件为：原视频有效，且六个可选固定槽位、有效 `output_language`、有效 `background_music` 中至少有一个。只有原视频时必须在分析、出图、Provider 请求之前拒绝。

### 4.2 组合路由规则

| 输入组合 | 必须走的路线 | 明确禁止 |
| --- | --- | --- |
| 仅原视频 + `output_language` | RunningHub Whisper → 逐句翻译 → TTS/人工配音 → RunningHub 对口型快速通道 | 故事板、Seedance、第二次整片分析 |
| 原视频 + 任意视觉替换 | 常规高保真复刻：源拆解、脚本确认、成对故事板确认、仅生成受影响区间 | 把所有 Cut 都送入生成模型 |
| 原视频 + 仅 `background_music` | 标准复刻音频路线：按源音乐窗口替换音乐；存在可验证歌词和可见歌手时让视频人物演唱上传歌曲 | 误入语言单改 TTS 路线；改变音乐入出点、循环、变速、变调或模型替代最终歌曲 |
| 语言 + 任一视觉替换 | 常规复刻路线；新语言台词、角色和时间窗进入脚本及 Seedance-20 最终编译 | 把它降级为仅对口型快通道 |
| UI 操作视频 + UI 截图/App 链接 | `opaque_ui_demo` 优先；截图/链接不再触发同一区间的 UI 重画 | OCR、语义改写或把该视频送入 Seedance |
| 尾部视频 | 替换源尾卡，按源入口转场壳自然结束 | 生成尾卡、补黑帧、补静音、循环或冻结 |
| App 链接/截图，且确有可重建 UI 区间 | `generated_ui_demo`，只使用官方/用户 UI 像素证据 | 将网页 HTML 或链接直接交给生成模型 |
| 模特 + 商品 + App/UI + 语言 + 尾部 + 音乐 | 同一源保真合同内按 Cut 混合路由；两次既有确认不变 | 用一个全局工具覆盖所有区间 |

## 5. 完整工作流目标

以下 12 个语义阶段和现有状态机保持不变；优化只发生在阶段内部的缓存、冻结合同和条件路由中。

| 阶段 | 必须产出/行为 | 可以跳过的条件 |
| --- | --- | --- |
| 1. `intake_bind` | 固定槽位与扩展的类型、SHA、时长和准入结果 | 无 |
| 2. `target_truth` | 商品/模特/UI 目标证据；App Store 只在生成 UI 确需消费时解析一次 | 无生成 UI 区间时跳过 App 解析 |
| 3. `dynamics` | 从第 0 帧到结尾的一次性 Cut、动作、镜头、叠层、ASR、OCR、音乐和静音证据 | 仅语言快通道只保留其所需 ASR/音频合同 |
| 4. `region_overlay_route` | 每个区间的 KEEP、REPLACE、COMPOSITE、OPAQUE_SPLICE、REMOVE 或 REINTERPRET 路由 | 无需生成的区间不进入后续生成 |
| 5. `intent` | 原视频钩子、卖点、证明、情绪、CTA 与新产品/App 价值映射 | 零生成区间时记录 `skipped` |
| 6. `script` | 可编辑的新文案/台词/歌词/说话人脚本；脚本确认 | 零生成区间或语言快通道按既有规则跳过 |
| 7. `region_duration` | 最多两段生成区间、精确 Cut 覆盖、全局/局部毫秒时间 | 零生成区间时跳过 |
| 8. `storyboard` | 单板或成对故事板、连续性检查、整套故事板确认 | 零生成区间/语言快通道时跳过 |
| 9. `prompt_audit` | Seedance-20 Invocation B、提示词和 Provider 请求完整性审计 | 语言快通道或零生成区间时跳过 |
| 10. `provider` | 真实生图/生视频/对口型任务的可恢复执行 | 仅本地确定性拼接时跳过不需要的 Provider |
| 11. `assembly` | 生成、源片段、UI、尾部和音轨按冻结时间轴合成 | 无 |
| 12. `qc_delivery` | 输出流、时长、黑帧、口型、文字、连续性、路线和最终 SHA 验证，然后只交付最终 MP4 | 无 |

任何阶段的 `enabled`、`skipped`、`failed`、`resumed` 状态、原因、输入 SHA、输出 SHA、工具版本和耗时必须写入任务的 `timing_log.json`。后续阶段读取安全的已完成阶段输出，不得重新跑分析。

## 6. 五项核心能力目标

### 6.1 成对故事板：服装一致且只确认一次

当计划需要两段生成时，系统先在后台完整生成一对故事板；第一张不能单独发给用户确认。第二张必须继承第一张末帧的状态，两个板均通过内部连续性检查后，才作为同一 storyboard revision 展示给用户一次修改和确认。

必须冻结并校验：人物身份、发型、脸部特征、体型、肤色；上衣/下装/鞋/饰品/妆容/纹身等服装锁；商品位置、持握手、朝向和接触点；第一段结束姿势、表情、视线、手势、镜头方向、环境和光线；第二段首帧的承接状态。

服装主色、图案、版型、饰品、发型、产品手位、画面左右方向或动作交接出现高优先级不一致时，只重新生成不合格故事板，不重做源分析、不重置脚本、不增加确认。用户改动任何影响连续性的内容后，必须重建受影响板或整对板并重新校验，仍回到同一个故事板确认入口。

**验收线：** 缺少第一段连续性输入时第二段不能生成；发现高优先级不一致时不能提交 Seedance；用户只能看到一套成对故事板和一个确认入口。

### 6.2 源内容时间轴、卖点替换与多人说话人

一次 `dynamics` 分析必须生成 `source_content_timeline`，并与 Cut 时间轴绑定。它至少包含：

- 画面文字的精确连续显示窗口：标题、字幕、卖点、CTA、品牌词和可读 UI 文本；不逐秒重复 OCR。
- 每段人声的时间、原文、类别（口播、对话、旁白、念白、演唱、不可辨识）和置信度。
- 音乐的入点、出点、淡入淡出、歌词、人声段、节拍锚点、转场音效、环境音和有意义静音。
- 每个 Cut 的动作、镜头、产品/App 证明、情绪变化、CTA 角色与证据。
- 每条事实的来源、证据 SHA、置信度、不确定性和可替换性。

Whisper/ASR 只回答“何时说了什么”。说话人分配仅对存在文字人声且有歧义的 Cut 执行：将声音窗口与可见人物、嘴部可见性、口型活动和镜头切换对应，输出稳定的 `CHARACTER_A`、`CHARACTER_B` 或 `VOICEOVER`。高置信度可进入脚本；低置信度在既有脚本确认页标为“待指定说话人”。未确认归属不得进入 Seedance-20 最终编译或 Provider。

每一个可替换的源文字/台词必须生成可编辑映射：`源句的作用 → 新商品/App 功能 → 机制 → 用户利益 → 可证明内容 → CTA`。脚本行必须显示源文本、源台词、角色、时间、新文本、新台词、目标证据以及字幕/口播/演唱/UI 类别。用户修改后，系统重新验证字数、时长、音节、节拍、说话人和镜头可见性，而不是重新分析原视频。

**验收线：** 每个有声音的生成 Cut 都能追溯到文字、角色和置信度；多人的每句话要么确认说话人、要么阻断；无法证明的卖点必须降级或删除，不允许编造机制、统计、效果、评价或承诺。

### 6.3 Seedance-20：准确念白、演唱和最终提示词编译

Seedance-20 的职责是编译和审计已确认合同，不是猜歌词、猜说话人或补写营销承诺。每一行声音内容必须同时进入 `line_contract` 和 `performance_line_contract`，至少包含：

- `line_id`、`cut_id`、角色标签、角色可见性和声音类型（`spoken`、`sung`、`instrumental`、`inaudible`）；
- 精确文本、语言、规范化文本、发音备注、全局/段内毫秒窗口和节拍锚点；
- 念白/演唱方式、情绪、强调、嘴部可见性、遮挡、头部运动、动作和表情限制；
- 卖点证据、Foley、静音和音乐策略，以及 ASR/人物/口型/节拍 QC 要求。

Invocation A 在脚本确认前检查文本是否装得进源时间窗、是否跨 Cut 或 Segment、是否与人物、画面、节拍和证据冲突。Invocation B 在故事板确认后，只能使用同一份已确认合同和同一 Seedance-20 快照编译最终 Prompt，禁止改词、漏词、加词、换人、错语种或跨 Segment。生成后，ASR 回转录、说话人、台词/歌词起止、节拍动作和口型均需校验；失败只回到相关脚本/音频合同或重生相关生成段，不允许重跑全片分析。

**验收线：** 最终 Prompt 的每句文本、人物、语言和时间都能追溯到已确认合同。成片出现未批准内容、错误角色、错误语言、超时或跨段台词时，必须阻断交付。

### 6.4 上传音乐与人物唱歌

`background_music` 是可选扩展，不改变七个固定槽位的顺序或含义。只上传原视频和音乐也可创建任务：它表示按原视频的音乐结构替换为上传歌曲，并在存在可见人物、可验证歌词和节拍条件时，让广告人物演唱上传歌曲。

上传音乐必须作为 Youdao `Audio` 资产注册，在请求中仅以内容项 `audio_url` + `role=reference_audio` 提供，最终 Prompt 仅以 `@Audio1` 指向它；顶层 `reference_audios` 永远禁止。

音乐处理有两个明确、不可混淆的模式：

1. **可验证演唱模式：** 上传音频能够取得可靠歌词、人声窗口和节拍锚点，脚本确认了演唱角色、歌词和时间窗。Seedance-20 以 `@Audio1`、歌词、歌手、口型限制和节拍编译视频表演；最终成片使用通过验证的原始上传音乐片段作为音频权威，不能用模型生成的歌曲替代。
2. **背景音乐替换模式：** 纯伴奏，或歌词/歌手证据不足且用户没有在脚本确认中修正。仍可按源音乐窗口替换 BGM，但不得声称人物准确演唱歌词；可见人物只能进行节拍表演或无歌词口型表演。

无论哪种模式，源视频的音乐切入、切出、淡入、淡出、停顿和转场点都是输出时钟。上传音乐必须用连续、可核验片段填充这些窗口；禁止循环、变速、拉伸、变调、静音填充、补黑或模型生成替代。音乐长度无法覆盖已确认窗口时必须阻断。最终混音回执必须绑定上传音频 SHA、实际切片 SHA、窗口、混音方法和最终视频 SHA。

**验收线：** 可见歌手必须具备歌词/音素对齐、口型、节拍和入出点 QC；无可见歌手或歌词不可靠时记录 `skipped` 原因；任何最终音乐都能逐段核对回上传文件，且不存在变速、循环、变调或模型替代。

#### 6.4.1 演唱请求、真实付费调用与压缩音频保真

“可验证演唱”不能只停留在内部脚本或测试 mock。Seedance-20 Invocation B 编译出的逐句演唱合同必须直接绑定到**最终提交给 Provider 的请求**：每句都必须保留 `line_id`、`speaker_id`、精确歌词、全局和段内时间窗、节拍锚点、人物可见性及口型/动作限制。不得把多句歌词简单拼成一段通用文本后就提交；这样会丢失“谁在何时唱哪一句”的商业验收依据。BGM 模式则必须明确写入 `No lyric lip-sync`，禁止把无歌词 BGM 伪装成演唱。

每次付费 `CreateVideo` 之前必须先写入不可变 `ProviderAttempt`：冻结请求 SHA、Seedance-20 编译制品 SHA 和段计划 SHA，状态依次记录 `SUBMITTING → RUNNING → SUCCEEDED`。若网络超时、进程中断或响应不完整，状态记为 `AMBIGUOUS`，恢复时必须先按已冻结请求和已有任务 ID 对账，绝不能重新创建付费任务。Provider 原始响应可作为任务临时制品保存，但阶段输出只能保存其制品引用和摘要，不能夹带二进制 `bytes`，避免已付费成功后因检查点序列化失败。

上传音乐的原始文件 SHA 用于溯源；MP3、AAC、FLAC 等压缩格式的“片段未被篡改”必须在解码后的规范 PCM 上核验，不能把压缩容器的字节偏移当作 PCM 样本。最终混音仍须绑定原文件 SHA、解码片段 SHA、窗口和最终视频 SHA。

**验收线：** 从 Invocation B 制品到真实 Provider payload 存在一一对应的逐句字段；异常恢复期间 Provider 创建次数不增加；压缩音频样例能通过正确的 PCM 片段比对；只有真实 API 返回任务 ID、真实媒体及最终 MP4 时，才可称为“本地 MVP 真实链路通过”。

### 6.5 受限 `remotion_react_ui`：只在最优的 UI 区间自动使用

不安装、不合并 Video ShotCraft。只借鉴其页面采集思路和少量 2.5D UI 表现，将其限制为现有 deterministic UI renderer 的候选适配器。

只有以下条件**全部**满足时，系统才自动选择 `remotion_react_ui`：

1. 有用户 UI 截图或已验证的官方 App Store 截图；
2. 当前区间为 `generated_ui_demo`；
3. 源视频该区间允许确定性 UI 重建；
4. `ui_truth_card`、`ui_render_contract`、源 UI 区间时长、画幅、旋转、安全裁切、转场壳、文字和布局均已冻结；
5. 需要的仅是白名单 2.5D 动作：轻微 perspective、分层 parallax、页面 translate 或轻微 scale；
6. FFmpeg/当前 deterministic renderer 不能以同等质量或速度完成；
7. 当前版本的适配器持有同案例、同合同、同身份 SHA 的基准启用回执。

任一条件不满足时直接回退 FFmpeg/现有 deterministic UI renderer，不等待、不重试外部 UI 工具。`opaque_ui_demo`、`source_ui_keep`、用户 UI 操作视频、尾部视频、无 UI 证据、要模型猜 UI 文案、要改变原视频节奏或没有通过基准的情况均禁止启用。

这里的“基准启用回执”必须是可读取、不可变的同案例报告，而不是任意 64 位 SHA 字符串。它至少绑定 `candidate=remotion_react_ui`、`eligible=true`、适配器版本/身份、`source_interval_contract`、目标 UI 证据、`ui_truth_card`、`ui_render_contract`、OCR、时序、黑帧和耗时结论。运行时必须重新校验报告摘要、所有绑定值和当前区间完全一致；伪造、缺失、过期或来自其他案例的回执一律回退。

Stage 4 必须从当前源区间事实重新投影 `source_interval_contract`。客户端或上游预填的合同只有在时长、画幅、旋转、裁切和转场壳与源事实完全一致时才可接受；不一致必须以明确错误阻断，不能让预填合同绕过源视频时间轴。

适配器只能复现冻结的页面、组件坐标、字体、文本、时长、画幅、旋转和转场壳，输出透明 UI 层或定长 UI MP4 交给既有时间轴合成。OCR、布局、状态顺序、动画抽帧、黑帧和最终时序仍须由独立 QC 验证；不得新增页面、镜头、字幕、BGM、SFX、转场风格或动效节奏。

**验收线：** 同案例每个 UI 状态和动画抽帧 OCR、布局均为 100%，没有黑帧、错误裁切或跳帧；时长、画幅、文字和转场壳一致。候选适配器不慢于基线，或质量有可量化提升且 p95 增量不超过批准阈值；否则永久回退既有 renderer。

## 7. 工具使用与加速策略

| 工具/能力 | 自动启用条件 | 不命中时的路径 | 必须留下的证据 |
| --- | --- | --- | --- |
| 源视频探测、动态/VLM 分析 | 每个正式任务一次 | 无替代；分析结果后续复用 | 源 SHA、覆盖范围、Cut/证据 SHA、耗时 |
| RunningHub Whisper/ASR | 有人声、歌词或需修改/保留音频文字 | 无人声/纯技术不透明区间跳过 | 音频 SHA、时间戳、模型/工作流、耗时 |
| OCR | 有可读叠层、字幕或确定性 UI | 不透明 UI/尾部不 OCR | 输入帧、文本区间、置信度、耗时 |
| App Store 解析 | 有 `app_store_url` 且 `generated_ui_demo` 确实消费官方 UI | 本任务内跳过，不抓取网页 | URL、官方像素、证据 SHA、跳过原因 |
| 说话人分离/口型对应 | 有台词且多角色或归属不清 | 单一可见说话人直接确定；低置信度待脚本指定 | 声音窗口、人物证据、置信度 |
| 歌词/人声/节拍分析 | 上传音乐，或源视频有可见演唱/节拍动作 | 普通无歌词 BGM 仅保留音乐窗口 | 音频 SHA、歌词/节拍证据、模式 |
| Seedance-20 specialists | 生成区间的冻结因素要求人物、镜头、动作、灯光、音频或多段连续性 | 只加载根编译器、`prompt` 与 `antislop` 必需模块 | 路由摘要、技能版本 SHA、编译合同 |
| RunningHub TTS/对口型 | 仅语言单改快通道 | 视觉替换任务走常规 Seedance 合同 | 行合同、Audio1、口型 QC |
| `remotion_react_ui` | 满足 6.5 的全部条件且为最优解 | FFmpeg/确定性 UI renderer | 决策、适配器身份、基准回执、耗时 |

所有工具都必须记录 `enabled` 或 `skipped`，并记录理由、输入/输出 SHA、版本、耗时和质量收据。任何一次成功的源分析、ASR、OCR、App Store 解析、歌词分析或故事板不得在同一任务的后续阶段重跑。

## 8. 速度目标与质量不降级原则

1. 常规任务的生产吞吐目标为 30 分钟内完成；这是测量目标，不可因为超时而取消有效的 Provider 等待或牺牲质量。
2. Seedance-20 Invocation A 的目标为 p50 ≤ 30 秒、p95 ≤ 60 秒、单次硬超时 120 秒；超时在付费调用前失败关闭。
3. 新增能力带来的非 Provider 主动处理增量不得超过匹配基线的 `min(120 秒, 10%)`。人工确认等待和 Provider 等待单独记账，不混入主动处理耗时。
4. 生图、生视频、ASR、TTS、App Store 解析、UI 重建和 QA 只对命中区间调用；零生成区间不出图、不生成视频、不生成故事板、不编译 Seedance Prompt。
5. 通过“冻结一次分析、区间路由、复用中间合同、并行无依赖资产/生成段、精准重试失败片段”加速；不得通过降低源分析深度、减少证据、跳过 QA、粗暴降低分辨率或把 UI/音频交给视频模型猜测来加速。

## 9. 质量门禁与失败边界

- 任一生成区间若缺少目标证据、时间窗、连续性锁、角色归属、歌词合同、UI 真值卡、路由证据或完整性审计，必须在对应付费调用前阻断。
- 源 UI 保留、用户 UI 操作视频和尾部视频是技术拼接素材，不能被语义分析、OCR 改写或当作 Seedance 视频参考。
- UI 文本、布局和状态顺序无法独立证明为 100% 时，`generated_ui_demo` 不得交付；必须回退至允许的源保留/不透明路径，或阻断等待有效目标 UI。
- 任意伪造、缺失、跨案例或与当前合同不匹配的 Remotion 基准回执，均不得激活适配器；`generated_ui` 这类历史/泛化路由也不得以兼容名义进入 `remotion_react_ui`，唯一允许的入口是 `generated_ui_demo`。
- 歌词不可靠、演唱角色不可见、口型不通过或音乐窗口覆盖不足时，不能伪称“人物精准演唱”；按 6.4 降为 BGM 模式或阻断。
- 付费 Provider 响应不完整、消息重复投递、Worker 重启或检查点失败时，必须保留现有尝试并先对账；不得因为系统内部错误再发起一次新的 CreateVideo。
- 最终 MP4 必须通过视频/音频流、画幅、帧率、时长、Cut 顺序、转场、黑帧、音画同步、文字、UI、人物/商品连续性和最终 SHA 的检查。任何硬失败不得交付。
- 失败修复只回到最小相关制品：台词问题回脚本/音频合同、故事板问题回故事板、某生成段问题回该段。除源合同损坏或验证失败外，不得重跑整片分析。

## 10. 批量执行、隔离与数据生命周期

- 一行批量任务对应一个独立 Job、输入清单、审批版本、Provider 尝试、临时对象前缀和最终视频；任务之间不得共享素材、提示词、App 证据、音频或缓存。
- 同一任务的安全阶段输出可由后续阶段复用；复用必须绑定 SHA，禁止写入本地路径、token、密钥或其他敏感字段。
- Provider 密钥只由环境变量或私有配置注入，绝不写入任务、日志、提示词、制品或下载链接。
- 成功后立即删除 `temporary/{job_id}/` 中的一切对象和本地工作目录；只保留 `final/{job_id}/result.mp4`。失败/中断 Job 在 TTL 到期后执行同等清理。
- 服务端部署前必须验证 Redis、对象存储、Provider、不可变技能包、必需能力端口、临时清理器和最终交付链路；任何一个缺失都不得接收或执行商业任务。

## 11. 必须通过的验收场景

| 场景 | 预期证明 |
| --- | --- |
| 仅原视频 | 拒绝；无分析、无生图、无 Provider 请求 |
| 原视频 + 仅语言 | Whisper/TTS/云端对口型；无脚本/故事板确认、无 Seedance |
| 原视频 + 商品图或模特图 | 一次深拆、卖点/脚本确认、故事板确认；仅受影响区间生成 |
| 原视频 + App 截图/商店链接 | 仅在需重建 UI 时取得官方证据；UI 文本和布局 100% 可证 |
| 原视频 + UI 操作视频 | 不透明拼接；不 OCR、不重画、不改写内容；画幅、时长、音频和转场通过 |
| 原视频 + 尾部视频 | 替换尾卡后自然结束；无尾部视频时删除源尾卡 |
| 原视频 + 上传音乐 | `@Audio1`、源音乐时间轴、最终音频 SHA；可验证时有人物演唱和口型 QC |
| 可验证演唱的真实提交 | Invocation B 逐句合同原样投影到最终 Provider payload；不允许通用歌词拼接替代 |
| Provider 超时或 Worker 重启 | 已有 `ProviderAttempt` 被对账恢复；CreateVideo 不重复提交，原始响应不会导致检查点序列化失败 |
| MP3/AAC/FLAC 上传音乐 | 以解码 PCM 验证准确片段与最终混音溯源，不因容器字节偏移误判失败 |
| 原视频 + 语言 + 模特 + 商品 + App/UI + 尾部 + 音乐 | 同一合同按区间混合路由；两次确认；不透明 UI/尾部绝不送入生成模型 |
| 超过 15 秒且需两段生成 | 成对故事板、服装/人物/产品交接、一次故事板确认、最多两次 Provider 视频任务 |
| 适合确定性 UI 的截图任务 | 自动命中 `remotion_react_ui`；有身份绑定的同案例基准、OCR/时序/耗时收据 |
| 不适合确定性 UI 的任务 | 自动跳过 Remotion，立即走既有路径；有明确跳过原因 |
| 伪造或跨案例的 UI 启用回执 | 不启用 Remotion，立即回退；预填且不匹配的源区间合同被阻断 |
| 两个说话人或多角色 | 每句确认说话人或在脚本确认处阻断；最终编译不允许待定归属 |
| 失败重试 | 仅重做失败故事板、合同或生成段；不重复整片分析、ASR 或重复付费提交 |

## 13. 完成定义

只有同时满足以下条件，才可以宣布本优化完成：

1. 本地 MVP 用真实 API 在第 11 节覆盖的关键场景中跑通，且有可查看的最终视频、Provider 任务 ID、最终媒体 SHA 与任务级证据；mock、合同测试或伪造回执不能替代这项证明。
2. 双故事板、源内容时间轴、多人台词、Seedance-20 最终编译、上传音乐演唱/BGM 路线和受限 UI 适配器均按本文条件运行；未命中条件时可安全快速回退。
3. 证明同一任务没有重复整片推理、重复 ASR/OCR/App Store 解析、重复故事板或重复付费 Provider 提交。
4. 自动化测试、黄金 UI 案例、音频/音乐 QA、端到端回归和清理验证全部通过；没有因优化而降低源视频拆解、卖点、App 解析、复合需求或深度复刻能力。
5. 服务端打包前已提供能力清单、私有配置模板、依赖版本/SHA、基准报告和临时清理验证；只有最终视频可以长期存在。

任何条件式能力未达到自己的验收线时，必须保持“未选中且快速回退”，不得阻塞核心复刻路线，也不得用未经证实的结果宣称完成。
