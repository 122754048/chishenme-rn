# USFR 新商品动作适配最小补丁设计

## 目标

在 `video-edit-v2` 现有爆款视频元素替换流程中，增强新商品、产品或 App 的正确使用、展示和反馈演绎。系统保留原片的镜头、节奏、人物轨迹和传播作用，但不机械继承只适用于旧商品的物理动作或特效。

本设计只增加商品意图理解、动作适配和执行完整性检查，不重构现有工作流，不增加用户审批阶段，也不增加 Seedance Prompt 的复杂度。

## 不可触碰边界

本补丁禁止修改以下任何内容：

- 人物身份绑定规则及其数据结构；
- 人物资产的 `model-identity-v3-local-crop` 格式、裁切、生成和校验规则；
- 人物服装证据策略；
- 人物 `@ImageN` 索引、源轨迹校准和持续轨迹绑定；
- 当前人物 Prompt 句式、顺序、权重和简洁程度；
- `imageUrls[N-1] == @ImageN` 及连续索引审计；
- 单次 Seedance 请求同时完成全部批准元素替换的方式；
- 其他人物、背景、服装、饰品、UI、语言、音频和尾片能力。

实施时，人物相关现有测试必须保持字节级预期或等价输出，不允许借本次修改进行重构。

## 核心原则

商品动作拆分为：

```text
原片动作 = 传播作用 + 旧商品专属操作 + 原片视觉反馈
目标演绎 = 保留传播作用 + 新商品适配操作 + 有证据的目标反馈
```

- 保留原片动作在剧情和传播中的作用，例如试用、证明、惊喜、对比或展示。
- 根据新商品的物理属性、使用方式和用户要求，替换旧商品专属操作。
- 根据素材、用户说明或可靠产品证据，替换视觉反馈。
- 删除新商品不支持的旧商品动作、旧商品特效和旧商品结果。
- 不从外观图片推导未经证明的成分、功效、价格或功能。

示例：原片“舔绿色糖果并出现绿色舌头”，目标为瓶装橙汁时，保留“试用并反馈”的传播作用，将操作转换为“拿起、开盖、饮用、吞咽”，将反馈转换为自然清爽或喜欢的表情，并删除舔舐和绿色舌头效果。

## 用户交互契约

### 第一次发布

系统分析原视频、新商品和用户要求后，只向用户发布一次简洁文字脚本。用户可选择：

1. **直接执行**：首次脚本即成为批准执行方案，立即进入后台编译和生成。
2. **修改后执行**：用户用自然语言修改脚本；修改内容即成为新的执行权威。系统在后台理解真实意图、规范化动作并直接执行，不再把修订脚本返回给用户，也不增加第二次确认。

只有当用户修改存在会实质改变产品用法、事实性卖点、品牌声明或最终画面的互斥解释时，才允许暂停并提出一个必要问题。表达不专业但意图唯一时，不得要求用户学习或编写 Prompt。

### 用户可见脚本格式

```markdown
# 视频替换脚本

## 核心信息

- 品牌：
- 产品/App：
- 主要展示重点：

## 视频脚本

| 时间 | 画面与人物动作 | 商品/App 操作与展示 | 口播/字幕 |
|---|---|---|---|
| 0.00-0.00s |  |  |  |

## 请确认

- 回复“直接执行”：按以上脚本开始生成。
- 直接写出修改内容：系统按你的修改理解并开始生成，无需再次确认。
```

用户文件不得展示 Prompt、哈希、索引映射、Matcher、segment plan、模型规则、绑定回执、审批边界、技术验收或复杂推理。

## 后台意图规范化

用户首次确认或修改后，后台把每条商品相关自然语言规范化为以下内部事实：

- `narrative_purpose`：该动作在原片中的传播作用；
- `target_operation`：新商品实际需要执行的动作顺序；
- `contact_relation`：人物、手、身体部位、设备或场景与商品的接触关系；
- `visible_result`：允许出现的可见反馈；
- `display_state`：包装、标签、屏幕或关键结构如何保持可见；
- `source_action_policy`：`preserve`、`adapt`、`replace` 或 `delete`；
- `evidence_basis`：用户明确要求、上传素材可见事实或可靠产品证据。

用户修改的语义优先于系统首次草稿。后台允许补齐完成动作所需的自然步骤，例如把“喝一口”规范化为拿起、开盖、饮用和吞咽；但不得增加用户未要求且证据不支持的功效或功能。

## 商品类型适配

所有类型使用同一套内部字段，不建设庞大的商品导演子系统。类型只用于选择必要的动作词汇：

- 食品和饮料：打开、取出、饮用或食用、吞咽、自然反应、包装展示；
- 护肤和彩妆：打开、取量、涂抹位置、质地、吸收或妆效展示；
- 电子产品：拿起、启动、连接、操作、设备反馈；
- App：进入界面、执行核心操作、展示结果、CTA；
- 服装和饰品：穿戴位置、穿戴动作、材质或动态细节；
- 家居用品：问题状态、使用动作、可见结果；
- 其他商品：依据已知物理结构和用户要求生成最小可执行动作链。

证据不足但用户已明确指定创意动作时，按用户指定动作执行；涉及真实性的功效、成分、价格、认证和功能声明仍需证据。既无证据也无用户说明且存在多种不兼容用法时，停止付费生成并请求必要信息。

## Prompt 编译边界

现有 Seedance Prompt 总体结构保持不变。营销分析、意图解释和商品类型判断不得直接进入 Prompt。

编译器只把用户批准的结果压缩为：

- 现有商品 `@ImageN` 替换绑定句；
- 必要的时间窗动作句；
- 必要的接触、展示和可见反馈；
- 原片镜头、轨迹、时间、环境和音频保留句。

示例：

```text
[对应时间窗]: Subject 1 picks up @Image2, opens the bottle, drinks it, shows a natural pleased reaction, then presents the bottle clearly to camera.
```

禁止向最终 Prompt 添加目标人群分析、痛点分析、营销解释、长篇负向约束、重复身份描述或用户未批准的动作。人物 Prompt 行不得由商品适配逻辑读取、改写、重排或重新生成。

## 无损执行检查

付费生成前必须验证以下链路：

```text
用户批准或修改的脚本行
→ 后台意图规范化结果
→ change_row
→ segment_plan
→ Seedance 精确时间窗动作句
→ 最终请求审计
```

以下任一内容丢失时，必须在付费调用前失败：

- 用户要求的新商品操作；
- 操作顺序；
- 人物与商品接触关系；
- 商品展示状态；
- 必须删除的旧商品动作或特效；
- 已批准的口播、字幕或时间窗。

不得退化为 `show the product naturally`、`use the product` 等无法执行和验收的泛化句。

## 测试范围

实施采用测试先行，至少覆盖：

1. 糖果舔舐转换为瓶装饮料开盖饮用，并删除舌头变色特效。
2. 不同商品类型的操作链按证据正确适配。
3. 用户选择“直接执行”时首次脚本进入执行链。
4. 用户修改后不产生第二次脚本审批，修改语义直接进入执行链。
5. 低水平自然语言能被规范化为短句动作，但不会生成无证据卖点。
6. 已批准商品动作不会在 `change_row → segment_plan → Prompt` 过程中丢失。
7. 最终 Prompt 保持当前紧凑结构和长度边界。
8. 所有人物绑定、人物资产、人物服装策略和多人物 Prompt 回归测试输出保持不变。
9. 商品、App、背景、服装、饰品、UI、语言和音频现有路线全部回归通过。

## 成功标准

- 新商品不再机械继承旧商品不适配的物理动作或特效。
- 用户只编辑业务脚本，不需要编写 Seedance Prompt。
- 用户直接执行或修改后执行都只有一个用户审批阶段。
- 用户修改后后台正确理解意图并直接生成。
- 最终 Seedance Prompt 保持当前简短、正向、直接的结构。
- 人物绑定及其全部规则没有任何行为变化。
