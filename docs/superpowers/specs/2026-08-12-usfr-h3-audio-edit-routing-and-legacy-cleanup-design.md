# USFR H3 音频编辑路由与旧流程清理设计

日期：2026-08-12

## 1. 目标

在 `universal-source-fidelity-replication` 的 `video-edit-v2` 中建立独立、可复用、不可与 Seedance 混用的 H3 音频编辑路线，覆盖：

1. 用户提供 MV 视频并指定新歌曲；
2. 用户要求把视频口播修改为指定语言。

同时清理被 H3 路线替代的旧实现、旧配置、旧测试和旧 bundle 引用，避免运行时同时保留多套互相冲突的音频流程。

本设计不修改人物、商品、App、服装、背景、首饰、配件等视觉替换的 Seedance 绑定规则。

## 2. 路由所有权

### 2.1 H3 独占任务

下列任务由 H3 独占：

- `h3_mv_song_full`：MV 全程演唱，使用指定歌曲；
- `h3_mv_song_with_protected_speech`：MV 包含演唱与台词、UI 口播等保护窗口；
- `h3_language_direct`：没有目标语言音频，由 H3 根据批准的新台词直接生成指定语言；
- `h3_language_audio_driven`：用户提供目标语言音频，或系统按批准内容准备完整目标音频。

上述任务不得进入 Seedance Provider 请求，也不得调用旧 song lip-sync AI App、旧 non-song lip-sync 或 language-only Seedance 路线。

### 2.2 Seedance 保留任务

Seedance 继续独占普通视觉编辑：

- 人物身份与衣着替换；
- 商品、App、背景、场景、服装、首饰、配件替换；
- 上述元素的现有多对象索引绑定和动作适配。

如果同一任务同时包含人物替换和指定歌曲，整体 Provider 路线使用 H3；人物图作为 H3 的 `图片1` 输入，不把 Seedance 的 `@Image1` 绑定合同注入 H3 Prompt。

如果 H3 独占音频任务同时包含商品、App、背景、服装、首饰、配件或多人物等其他视觉替换，只有该组合已经存在明确的 H3 能力回归测试时，才允许在一次 H3 请求中执行。未经验证的组合返回 `manual_review_required`，不得静默串联 Seedance 与 H3，也不得把 Seedance 绑定 Prompt 翻译后猜测性注入 H3。

## 3. H3 与 Seedance 的硬隔离

### 3.1 H3 契约

- 接口：`/openapi/v2/minimax/hailuo-h3/multimodal-to-video`；
- 引用语法：`视频1`、`图片1`、`音频1`；
- 数组映射：`videoUrls[0] -> 视频1`、`imageUrls[0] -> 图片1`、`audioUrls[0] -> 音频1`；
- Prompt 使用简短、直接的视频编辑句式，依据 MiniMax H3 用户手册和视频扩写 Prompt 指南；
- 禁止出现 `@Video1`、`@ImageN`、`@Audio1`、Seedance binding receipt 或 Seedance Prompt 合同文本。

### 3.2 Seedance 契约

- 保留现有 `@Video1`、`@Image1..N`、连续数组索引与 Provider-only binding receipt；
- 禁止使用 H3 的“视频1、图片1、音频1”引用编译方式；
- 禁止接收 MV 指定歌曲或指定语言的 Provider 路由。

### 3.3 提交前拦截

付费调用前必须拒绝：

- H3 Prompt 含任何 `@Video`、`@Image`、`@Audio`；
- Seedance Prompt 使用 H3 索引词作为资产引用；
- MV 指定歌曲任务的 H3 `视频1` 仍含音轨；
- 混合 MV 没有完整的保护窗口；
- H3 音频1与视频1时长不匹配；
- 指定语言任务没有批准的新台词或目标音频；
- 指定语言不属于 11 种稳定对白语言，且用户没有明确批准实验性生成；
- 相同请求摘要已提交。

## 4. MV 指定歌曲流程

### 4.1 音频分析

源视频音频只分析一次，冻结以下时间窗：

- `singing`；
- `spoken_dialogue`；
- `ui_monologue`；
- `music_only`；
- `sfx_ambience`；
- `silence`。

置信度不足以区分演唱与台词时停止付费生成，不能默认整片演唱。

### 4.2 全程演唱

当整个有效区间均为演唱，且没有需要保留的台词或 UI 口播：

1. 从源视频生成等时长无音轨 `视频1`；
2. 从指定歌曲截取等时长 `音频1`；
3. 一次提交 H3；
4. 目标人物存在时提供 `图片1`。

有换人时 Prompt：

```text
将视频1中的人物替换为图片1中的人物，并全程演唱音频1中的歌曲。人物口型与音频1同步，保持视频1的镜头、动作、背景和剪辑节奏。
```

无换人时 Prompt：

```text
视频1中的人物全程演唱音频1中的歌曲。人物口型与音频1同步，保持视频1的画面、动作和剪辑节奏。
```

### 4.3 演唱与受保护口播并存

当视频包含台词或 UI 口播：

1. 冻结演唱窗口和保护窗口；
2. 生成与视频等长的复合 `音频1`；
3. 演唱窗口使用指定歌曲对应时间片段；
4. 保护窗口使用原台词、UI 口播及批准保留的声音；
5. 其他窗口按证据保留环境声、音效或静音；
6. `视频1` 必须移除全部原音轨；
7. 一次提交 H3。

通用 Prompt：

```text
将视频1中的人物替换为图片1中的人物。使用音频1作为完整声音：[演唱窗口]演唱音频1中的歌曲，[口播窗口]按音频1中的口播展示原视频操作。人物口型与音频1同步，保持视频1的镜头、动作、背景和剪辑节奏。
```

歌曲默认按原视频时间轴连续映射。保护窗口不会压缩歌曲时间；例如视频 `0-4s` 使用歌曲 `1:30-1:34`，视频 `4-10s` 保留口播，视频 `10-15s` 使用歌曲 `1:40-1:45`。用户在文字脚本中可以改为“歌曲暂停后续播”。

## 5. 指定语言流程

### 5.1 稳定对白语言范围

H3 当前稳定支持输出以下 11 种视频原生对白语言：

- 阿拉伯语；
- 中文；
- 英语；
- 法语；
- 德语；
- 意大利语；
- 日语；
- 韩语；
- 葡萄牙语；
- 俄语；
- 西班牙语。

该列表表示成片原生音频中的对白输出语言，不表示 Prompt 输入语言。用户可以用中文编写编辑要求，再让 H3 输出上述目标语言。

其他目标语言可以作为实验性请求进入用户脚本，但必须明确标记为 `experimental_language`，不得使用“稳定支持”的口径。该提示和用户是否继续的选择包含在现有唯一一次文字脚本确认中，不增加新的审批门；如果用户没有明确继续，则停止生成。

该白名单不外推为歌曲演唱语言保证。MV 歌曲的语言和歌曲身份必须以用户上传音频及成片音频验收为准。

### 5.2 文字脚本

先识别原台词并生成目标语言台词。用户可见脚本仅展示：

```text
时间：
人物动作：
新口播：
新字幕：
```

用户直接执行，或修改后由后台理解真实意图并直接执行，不发布第二份脚本。

### 5.3 H3 直接生成语言

没有目标音频时：

```text
将视频1中人物的台词改为德语：“[批准台词]”。人物使用德语自然说出该台词，口型与台词同步。保持视频1的画面、人物动作和镜头。
```

多段台词按时间窗逐行声明，避免冗长描述。

### 5.4 音频驱动语言修改

用户提供目标语言音频时：

```text
将视频1中人物的台词替换为音频1，口型与音频1同步。保持视频1的画面、人物动作和镜头。
```

如果还需保留环境声或音效，先制作等时长复合音频，并向 H3 提供无音轨 `视频1`。新旧口播不得同时进入模型。

## 6. 超过 15 秒

H3 单段限制为 15 秒：

1. 自然 Cut 优先；
2. 没有合法 Cut 时使用固定 24 fps 帧级边界；
3. 不切断一句台词、连续歌词或完整动作；
4. 每段单独生成无音轨 `视频1` 和等时长 `音频1`；
5. 每段独立 H3 请求，之后按冻结时间轴拼接；
6. 文字脚本展示分段内容，但不增加新的用户审批门。

超过 15 秒无法保证一次 H3 请求，Skill 不得向用户承诺单次生成。

## 7. 验收

### 7.1 MV

必须同时验证：

- 人物身份与目标图一致；
- 演唱窗口口型成立；
- 演唱语言与目标歌曲一致；
- 输出歌曲与目标歌曲的相似度高于原歌曲；
- 受保护口播逐句完整；
- 口播窗口没有歌曲覆盖；
- UI、镜头和动作基本保留；
- 没有原歌曲残留。

只验证“存在演唱”或“存在音轨”不构成通过。

### 7.2 指定语言

必须验证：

- 目标语言识别正确；
- 批准的新台词完整；
- 原语言没有残留；
- 口型与新台词基本同步；
- 未编辑画面基本保留；
- 自动字幕没有破坏性错误。

## 8. 旧流程清理

清理遵循“先证明不可达，再从运行闭包删除”，不能只在文档中标记废弃。

### 8.1 删除的运行能力

验证依赖后删除：

- language-only 经 Seedance 生成的 Provider 路由和 Prompt 分支；
- 旧 pinned song lip-sync AI App 的调用、segment manifest、assembly render 与相关配置；
- `runninghub_final_lip_sync.py` 中不可达的旧 non-song/language lip-sync；
- 只服务上述旧路线的常量、环境变量、bundle manifest 条目、验证目录和测试夹具；
- 文档中关于“语言修改走 Seedance”和“MV 生成后再跑 song lip-sync”的现行说明。

### 8.2 保留但改写语义

- `language_only` 保留为 intake 和任务分类字段，但 Provider owner 改为 H3；
- 音频时间窗分析、台词识别、用户脚本确认、确定性音频拼接、24 fps 分段和防重复提交继续复用；
- 现有人物资产 `1024x1024 PNG` 规则继续用于 H3 的单人物 `图片1`。

### 8.3 保留的独立能力

以下不因本迁移删除：

- 与指定语言无关的批准后 off-camera voiceover TTS fallback；
- Seedance 普通视觉编辑及其多对象绑定；
- UI 确定性拼接、字幕/CTA/尾帧等后期能力。

### 8.4 历史证据

不再运行但需要保留审计价值的实验 Prompt、任务 ID 和结果，仅保留在 `analysis/private` 或非 bundle 历史文档中，不进入本地 Skill 的 runtime、manifest、测试闭包或发布包。

## 9. 实施安全顺序

1. 生成当前运行依赖图和动态导入扫描；
2. 先写 H3 路由、Prompt 编译与请求审计的失败测试；
3. 实现 H3 Provider、无音轨视频和复合音频准备；
4. 将 language-only 和 MV 指定歌曲入口切换到 H3；
5. 运行新路线测试并确认通过；
6. 删除旧 Provider 路径及相关闭包；
7. 修正 bundle manifest、验证目录和部署文档；
8. 运行全量回归，证明 Seedance 视觉编辑未受影响；
9. 用静态搜索和动态导入测试证明旧路线不可达且无残留发布引用。

本地 Skill 根目录与 `usfr-server` 部署包必须由同一变更同步更新。任何一侧仍保留旧路由、旧 bundle 条目或相反的模型说明，都视为迁移未完成。

## 10. 完成标准

- 四条 H3 路由均有单元测试和请求契约测试；
- H3/Seedance Prompt 引用混用会在付费调用前失败；
- 全程演唱与混合口播 MV 均有固定回归案例；
- 指定语言的直接生成与音频驱动均有固定回归案例；
- 旧 Seedance language-only、旧 song lip-sync AI App 和旧 non-song lip-sync 不在运行闭包；
- bundle 闭包、Skill 回归和部署包测试全部通过；
- 人物、商品、App、场景、服装、首饰与配件的 Seedance 绑定测试保持通过；
- 不增加新的用户审批门，用户仍只看到文字脚本和最终 MP4。
