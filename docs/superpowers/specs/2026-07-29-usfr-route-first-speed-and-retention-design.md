# USFR 路由优先、单次分析与临时文件收敛设计

日期：2026-07-30

## 1. 目标

在不改变现有输入入口、脚本确认、故事板确认、Seedance 生成、UI 处理、音频处理、合成和最终质量门槛的前提下，让 USFR 更快进入最终视频生成，减少对同一内容的重复推理、重复审核和无用文件生成。

唯一业务终点是：生成并交付通过 QC 的最终复刻视频。中间推理、证据和文件只有在确实影响路线、用户确认、付费请求、故障恢复或最终质量时才允许产生。

## 2. 不允许改变的能力

- 爆款原视频必传，最长 30 秒；其他变化选项至少提交一个。
- 支持人物、实物商品、APP、UI 截图、UI 操作视频、尾部视频、音频、目标语言和复合需求。
- 每个公共任务都必须先出现文字脚本、再出现故事板，且都允许用户修改和确认。
- 不降低原视频镜头、动作、转场、节奏、卖点、文字、台词、声音和时序的复刻要求。
- 不降低目标人物、商品、APP/UI、歌词、指定语言和对口型约束。
- Provider 付费任务仍需请求摘要冻结、幂等去重和歧义恢复，禁止盲目重提。
- 最终 QC 的音视频流、黑帧、时长、时间轴、UI 文字、关键卖点和高关键因素门槛不降低。

## 3. 当前主要浪费

当前工程已经有 `analysis_scope`，但仍需要把它从“提示信息”提升为所有工具调用的强制执行合同。主要浪费来源如下：

1. 在明确素材角色后，仍有阶段可能做全量语义分析。
2. 同一源视频在分析、脚本、故事板、Prompt 和 QA 阶段被重复读取或重新解释。
3. ASR、OCR、App Store、UI 重建、歌词、Seedance 专项能力没有统一的调用闸门。
4. 控制帧、故事板参考帧、QA 抽帧分别生成，造成重复解码和大量 PNG。
5. GPT 同时承担可由代码完成的哈希、对齐、字段一致性和重复审核工作。
6. 低风险路线和高风险复合路线使用近似相同的 QA 深度。
7. 成功后仍保存大量中间图片、音频、JSON、Provider 文件和缓存。

## 4. 方案选择

### 方案 A：所有路线继续深度分析，只减少 Prompt 长度

改动小，但只能降低少量 GPT 时间，不能解决重复解码、重复 ASR/OCR、故事板和 QA 文件过多的问题，不采用。

### 方案 B：完全按素材入口直接路由，不再检查源视频内容

速度最快，但会误判源视频中是否存在 UI、唱歌、多人台词、尾部卡片和需要生成的区间，质量风险不可接受，不采用。

### 方案 C：确定性预路由 + 一次轻量结构检查 + 命中区域单次深度分析

采用此方案。先根据固定槽位决定“哪些工具理论上可能需要”，再用一次低成本结构检查确认源视频中实际存在的区间，只对最终命中的区间做一次必要的深度分析。后续所有阶段复用同一冻结证据，不再重新理解源视频。

## 5. 总体流程

```text
固定槽位绑定
  -> 单次 ffprobe/媒体探测
  -> 确定性预路由 analysis_scope
  -> 一次轻量结构时间轴检查
  -> 冻结实际区间与工具调用表
  -> 只对命中区间执行 VLM/ASR/OCR/App Store/歌词/UI
  -> 生成并确认文字脚本
  -> 复用同一证据生成并确认故事板
  -> 只对生成区间执行 Seedance-20 和 Provider
  -> 确定性合成
  -> 轻量 QC，必要时升级专项 QC
  -> 上传最终 MP4
  -> 清理全部临时文件
```

## 6. 两级路由

### 6.1 第一级：素材预路由

该步骤禁止调用 GPT、VLM、ASR、OCR、App Store 或 Provider。输入只允许是固定槽位清单、扩展音频和 `output_language`。

输出必须列出每个工具的 `required`、`deferred` 或 `skipped`，并生成稳定的 `scope_sha256`。`skipped` 表示本任务永远禁止调用；`deferred` 表示只有第二级路由证明存在对应区间时才能调用。

### 6.2 第二级：源视频结构路由

只执行一次低成本结构检查，确认：

- Cut 和转场边界；
- 人物可见区间；
- 商品交互区间；
- UI/屏幕操作区间；
- 尾部卡片区间；
- 可见讲话、唱歌或纯背景音乐区间；
- 需要保留、替换、拼接、生成或删除的区间。

该步骤不做卖点长篇分析，不生成用户文案，不做全视频 OCR，不读取 APP 商店，不进行深度 QA。它只把 `deferred` 工具提升为 `required` 或降为 `skipped`，形成最终 `execution_scope`。

## 7. 各路线允许调用的工具

| 路线 | 必须调用 | 条件调用 | 禁止调用 |
|---|---|---|---|
| 只改语言 | ffprobe、时间戳 ASR、文字脚本、故事板、TTS、目标语言校验、对口型、最终 QC | OCR 仅源视频存在需替换文字时 | App Store、商品分析、全量 VLM、UI 重建 |
| 只换人物 | 结构时间轴、人物/表演区间 VLM、文字脚本、故事板、Seedance-20 人物/动作/镜头、QC | ASR 仅命中说话或唱歌区间；OCR 仅文字受影响 | App Store、无关 UI、全视频 OCR |
| 只换实物商品 | 结构时间轴、商品交互区间 VLM、卖点映射、脚本、故事板、Seedance-20 商品/动作、QC | ASR 仅需要改台词；OCR 仅商品文字受影响 | App Store、无关人物深描、全视频 UI |
| APP/数字产品 | 结构时间轴、APP 卖点、脚本、故事板、必要生成区间、QC | App Store 仅生成 UI 或卖点证据需要；OCR 仅 UI ROI | 无生成 UI 时读取 App Store；全视频 UI OCR |
| UI 截图 | UI 区间定位、ROI OCR/布局/交互、脚本、故事板、确定性 UI 重建、QC | 受限 Remotion 仅确定性重建为最优解 | ShotCraft 全局运行、Seedance 生成 UI 文字 |
| UI 操作视频 | UI 区间定位、技术探测、时间映射、脚本、故事板、确定性拼接、QC | 截图只做样式校准；有限变速只在安全范围内 | OCR/语义解释新 UI 视频、Seedance 重画 UI、使用其默认音轨 |
| 尾部视频 | 尾部区间定位、技术探测、转场和时长映射、脚本、故事板、拼接、QC | 无 | 尾部语义重写、Seedance 重做已提供尾部视频 |
| 上传音频，源视频为 MV | 轻量 MV 判定、歌词提取、人物/歌词/时间线合同、脚本、故事板、Seedance-20 音频编译、必要对口型、QC | 多人分配仅存在多人可见演唱时 | 非歌曲 ASR 反复转写、把歌曲仅当 BGM |
| 上传音频，源视频非 MV | 音频探测、原音乐切入切出时间轴、脚本、故事板、背景音乐替换、QC | 人声冲突时做一次轻量语音窗口检查 | 歌词提取、唱歌 Prompt、唱歌对口型 |
| 复合需求 | 合并各命中工具的最小并集 | 只对冲突或低置信度因素升级 | 回退到全部工具全量运行 |

## 8. 一次分析、多阶段复用

每个源视频只允许生成一个 `source_evidence_bundle`。它由以下内容组成：

- 探测结果；
- Cut/转场/区间时间轴；
- 命中区间的自适应关键帧；
- 必要的 ASR、OCR、音频事件和卖点证据；
- 目标人物、商品、APP/UI 证据；
- 冻结的路线、置信度、疑点和工具执行记录。

脚本、故事板、Seedance-20、合成和 QA 只能读取该证据包及用户最新确认版本。禁止再次对完整源视频进行常规 VLM 分析。只有证据损坏、时间轴冲突或低置信度硬阻塞时，才允许对单个区间补充一次专项证据。

## 9. 推理收敛

- GPT 只做一次源语义理解和一次脚本草拟。
- 用户修改脚本后，禁止重新分析源视频；只重算受影响 Cut 的脚本派生字段。
- 故事板修改只重生成受影响的故事板图，不重跑源视频分析和卖点分析。
- Seedance-20 Invocation A 复用源证据；Invocation B 只编译最新已确认脚本和故事板。
- 哈希、时间窗、Cut 覆盖、Prompt 字段完整性、revision、路由排除和 Provider 去重全部由确定性代码校验。
- 同一 Prompt 版本只允许一次 dry-run；确定性 parity 检查不再请求 GPT。

## 10. 文件收敛

### 10.1 允许产生的文件

- 一份源探测结果；
- 一份路线和时间轴合同；
- 一份共享关键帧清单；
- 必要区间的少量关键帧或 ROI；
- 当前文字脚本 revision；
- 当前故事板 revision；
- 当前 Provider 输入与输出；
- 最终合成文件和 QC 报告。

### 10.2 禁止产生的文件

- 逐帧 PNG；
- 同一关键帧的分析版、故事板版、QA 版多份副本；
- 未命中路线的 ASR、OCR、App Store、UI 或歌词文件；
- 每次 GPT 检查都生成完整重复 JSON；
- 已被新 revision 取代的长期中间文件；
- 成功后继续保存的 Provider 下载文件、切片、WAV、临时拼接和缓存。

### 10.3 保存规则

- 本地 Skill：成功后只长期保留最终视频；源素材保持在用户原位置，不复制到长期目录。
- 服务端：原始 OSS 素材和最终 OSS MP4 永久保留；MinIO 与 Redis 为临时数据。
- 成功任务：最终视频上传并验证后立即清理可再生中间文件；审核内容可随任务 Token 保留，但不保留重复媒体副本。
- 最终失败任务：默认立即清理 MinIO 媒体和可再生故障文件；错误码、公开错误信息和最小任务状态随 Token 元数据保留 7 天。
- 任何清理都不能删除原始 OSS 素材和永久最终视频。

## 11. QA 分级

### 11.1 每条视频都执行的轻量 QA

- MP4 可解码；
- 视频流和必要音频流存在；
- 时长、画幅、FPS 和时间轴一致；
- 拼接边界无黑帧；
- UI/尾部区间位置正确；
- 生成区间的人物、商品和关键文字没有明显丢失；
- 最终文件已上传且 SHA/大小/MIME 一致。

### 11.2 只在以下情况升级专项 QA

- 路由置信度低；
- 多人台词归属不明确；
- MV/非 MV 判定接近阈值；
- UI OCR 或布局未达到硬门槛；
- 生成区间出现人物、商品或动作不一致；
- 音画、歌词或对口型偏差超过阈值；
- 技术硬错误或 Provider 输出异常。

专项 QA 只检查失败因素和对应区间，禁止再次做全视频综合审核。

## 12. 质量影响

按本设计执行，不应降低质量。被删除的是重复工作，不是关键证据：

- 保留一次完整而有针对性的源证据；
- 保留脚本和故事板两次用户确认；
- 保留 Seedance-20 最终编译和确定性请求审核；
- 保留所有技术硬门槛和低置信度升级能力；
- 不分析不会进入最终视频的 opaque UI 和尾部内容。

主要风险是路由误判。解决方式不是恢复全量分析，而是让第二级结构路由输出置信度，并仅对低置信度因素做局部升级。

## 13. 性能目标

以下是工程目标，不是对外时长承诺：

- 确定性预路由：1 秒内，不调用模型。
- ffprobe 和轻量结构路由：普通 30 秒视频目标 5 到 15 秒。
- 单次语义分析：p50 不超过 30 秒，p95 不超过 60 秒，硬超时 120 秒。
- 同一视频完整分析次数：1 次。
- 同一音轨常规 ASR 次数：最多 1 次。
- 同一 UI 区间 OCR 次数：正常 1 次，失败专项复检最多 1 次。
- 同一故事板 revision 的生成次数：1 次；用户修改只重做受影响图。
- 同一 Prompt revision 的 GPT/Seedance-20 编译：1 次。
- 不计 Provider 排队，标准人物/商品路线目标提升单位时间产量 1.8 到 3 倍；复合 APP/UI/音频路线目标提升 1.3 到 1.8 倍；主要为确定性拼接的路线目标提升 3 到 10 倍。

## 14. 验收标准

- 所有测试路线仍严格出现脚本和故事板两个用户确认点。
- 测试日志能证明每个工具是 `required`、`skipped` 或由 `deferred` 单次升级。
- 同一任务没有第二次完整 VLM、ASR、App Store 或 OCR 调用。
- 故事板、控制帧和 QC 复用共享帧证据。
- 成功后中间目录只剩最终 MP4，或服务端只剩永久 OSS 结果与必要短期任务元数据。
- 36 条验证矩阵无 UI、文字、卖点、人物、商品、声音、时间轴和黑帧回归。
- 与当前基线相比，质量评分不下降，单位时间完成视频数量达到上述目标区间。

## 15. 非目标

- 不删除脚本或故事板确认。
- 不降低 QC 阈值来换速度。
- 不改成单一模板化视频生成。
- 不让 ShotCraft、Remotion、App Store、OCR、ASR 或 Seedance 全局运行。
- 不在本方案中增加用户、账号、订单、计费和历史产品体系。
